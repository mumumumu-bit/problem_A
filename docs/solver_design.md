# 第一轮求解器：模型与工程说明

本文件描述 `src/npu_scheduler` 的实际实现。官方 `code/`、`data/` 保持原样。当前是六个代表算例的开发验证版本，不能称为已经完成 100 例正式实验或证明了国赛竞争力。

## 实现边界与目标

解由有序 blocks 与 block→core 向量组成，每核顺序是全局 block 拓扑序的投影。真实目标采用字典序 `(makespan, added_copy_bytes)`；内存、通信和 Cache 估计仅用于候选排序。所有被输出的 incumbent 必须先通过对应问题的官方评估。

`GraphData` 一次解析原图，保存连续非 COPY 操作索引、原始 ID 映射、操作类型、pipe、cycles、tensor 超边、生产者/消费者、输入输出字节、稀疏操作邻接表、拓扑序、深度、上行/下行关键路径秩、弱连通分量和 pipe 工作量。COPY 节点不参与切图，但其路径在依赖图中收缩保留。共享输入采用 tensor→consumer 超边表示，避免建立二次规模的稠密亲和度矩阵。

## 初解

1. Load-balanced：确定性拓扑序、工作量切分、累计工作量最小核心。
2. Affinity：前驱优先的局部性拓扑序，优先相连或共享输入的操作；按估计完成时间扣除同核输入复用收益分配。
3. Critical：上行关键路径秩决定 ready-list 优先级，计入前驱可用时间与跨核通信。
4. Pipe：局部性分块与关键路径 ready-list，分配时同时考虑 PIPE_M / PIPE_V 累积工作量。

另评估一个整图单核放置候选，避免长依赖链被强制切分而显著退化。此候选不替代加速比定义中的官方独立单核基准。

Coarsening 使用两层聚合：先在拓扑序上形成连接/共享输入较强的 atomic runs，再按总工作量预算聚合成 coarse blocks。以总 cycles/(核数×粒度参数) 控制预算，采用 4、12、32 三种粒度。聚合连续拓扑区间保证商图无环；允许合并相邻独立分支以降低问题 1 的 Task 切换开销。

目前 coarsening 的内存信息尚未作为默认硬约束：总 tensor 量不能代替同时存活量。内存估计仅记录与校准，不凭未验证阈值删除候选。

## VNS 与合法性

实现 N1 核移动、N2 核间交换、N3 相邻独立块换序、N4 相邻块合并、N5 按工作量二分重块、N6 边界操作移动、N7 强连接块共同放置、N8 关键路径优先移动。

每轮最多产生 `candidate_pool` 个去重候选，使用粗粒度依赖完成时间、通信量、pipe 工作量排序，仅评估前 `top_k` 个。真实目标改善则重置到 N1，否则转入下一个邻域。连续扫描完八个邻域或达到轮次/时间/次数预算则停止。这是确定种子的变邻域下降，不包含随机接受劣解的 SA，也不宣称全局最优。

全局 block 顺序保证商图数据边和核心顺序边无环。但问题 2/3 还会产生 Pipe FIFO、内存复用和跨核 COPY 依赖，存在额外执行等待环风险。此类候选记录为不可执行，交由官方校验拒绝，不允许作为输出。

## 估计器限制

通信估计按 tensor 的消费 Task/核心集合统计，避免简单边求和造成所有广播都按消费者操作重复计数。估计执行时长使用 block 的最大 pipe 工作量与前驱到达时间，未精确模拟共享 DDR 竞争，因此只是排序指标。

内存估计以 block 粒度的首次/末次触及构造存活区间，累计每个 Task/核心的 L1/UB 超容量量。它没有复制官方 Spill 调度；block 内部顺序、COPY 重命名与带宽竞争会导致显著误差。默认 `memory_weight=0`，应由真实 Spill/Makespan 的相关性和独立消融支持后才开启。

Cache 估计跟踪共享输入逻辑 tensor ID、大小、首次预计读取时间及其间的不同插入字节。首次 DDR 读取未结束的并发请求不被视作命中；容量和 Cache 带宽均读取官方 config。它是插入距离代理，未复制 FIFO 事件模拟，也未预测所有 Spill 再读取，默认 `cache_weight=0`。真实命中率只读取官方 `cache_stats.hit_rate`。

## 预算、缓存与复现

默认 seed=2026，单次求解软预算 120 秒、最多 36 次候选评估。规模选择器对 medium/large/extra-large 限制最多 40/26/20 次（与配置取较小值）。四个初解族均尝试后，若种子阶段已用去45%的时间预算，就转入VNS；优先覆盖不同粒度，避免预算只用在粗粒度上。超过10,000个非COPY操作时，不把昂贵整图单核评估作为常规种子；只有全部种子不可执行才使用紧急兜底。该调整来自 development_v1 中大图整图评估挤掉搜索预算的实测结果。

预算在两次官方调用之间检查，一次进行中的评估不能被抢占；它不是硬实时上限。固定评估次数且未触及时间预算时结果可重复；墙钟预算生效时不同机器可能完成不同数量的候选。

缓存键包含完整原图内容哈希、官方源码哈希、官方 config 内容、问题编号、核心数、完整输出方案。改变搜索参数不改变同一方案的物理评估结果，因此搜索参数记录在 run manifest 中，不用于重复计算同一物理方案。持久化使用同目录临时文件和原子替换，支持多进程复用。

完成的 benchmark job 支持跳过续跑；中断的 job 重新生成确定性候选，借助显式指定的 `--cache-dir results/evaluation_cache` 复用已有结果。跨不同源码/配置/数据的 run 目录会被拒绝复用。冷缓存开发实验默认不启用持久缓存，避免运行时间被旧结果污染。

并行仅在独立 case/problem/core job 级，默认两进程；每个 evaluator 内部顺序运行。`manifest.json` 记录 Git commit、未提交状态、源码哈希、Python/平台/依赖版本、参数与随机种子；方案、逐候选日志、指标、CLI 输出分别保留。开发实验另保存 `source_snapshot.zip`，可重建原始实验版本。

## 第一轮范围

固定开发集：small=001/019，medium=005/050，large=025/085；覆盖独立卷积分支、混合 DAG、深依赖 Transformer 类运算与重复矩阵运算结构。全部 100 个 case 只做读入和结构审计。第一轮实际比较三种累计阶段：Baseline、Multi-seed、Multi-seed+VNS。完整 A0～A4、CP-SAT/SA/GA 消融、参数冻结和全量正式实验属于后续阶段，尚未执行。

`competition.yaml` 目前是较大预算的研究预设，尚未冻结为最终竞赛配置。任何“默认最强组合”的结论仅限当前开发集与预算。
