# 对现有建模草案的事实校正

原建模资料保留以便追溯；本说明用于后续论文修订。

| 草案内容 | 校正及依据 |
|---|---|
| 最大约 1,650 ops | 100 例实际扫描范围为 766～38,666，总节点数包含 COPY；以 `results/dataset_audit.csv` 为准。 |
| 总张量量大于容量就必然 Spill | 错误。容量约束针对同时存活张量；相互独立或顺序释放的大量张量可以不溢出。 |
| 直接设计 Spill 或地址分配策略 | 本题选手仅提交两字段方案。Spill、重命名、虚拟容量复用依赖由官方 Step2/3 决定，适配层不得替换。 |
| 用操作类型推断 pipe | 官方使用显式 `pipe` 字段；实现保持该字段。 |
| 连通 DAG 保证拓扑序唯一 | 连通不保证唯一；官方也不要求计算子图必须连通。使用确定性并列规则获得可复现顺序。 |
| 权重很小，搬运惩罚就只是平局打破者 | 仍可能颠倒不同 Makespan 解的优劣。改为严格字典序 `(Makespan, Added Copy)`。 |
| 溢出估计精度≤25%、Cache趋势高度相关 | 草案未提供可重现验证证据。必须从真实 trial 日志重新计算，不能写作已验证结论。 |
| 同时访问共享输入必然命中 | FIFO 在读取完成后插入；同时发起的读取可能全部 miss。命中不会刷新插入顺序。 |
| Spill backing ID 不同，所以无法 Cache 复用 | 问题3 `copy_tensor_info` 使用片上 tensor 的 `logical_tid`，重命名 tensor 可保留同一逻辑身份。 |
| 以总耗时均值相除求平均加速比 | 应先算每例单核/多核比值，再取算术平均。 |
| 问题2必优于问题1，L2同方案必定加速 | 不能由资源直觉替代官方结果。启发式核内顺序和事件交互可能改变性能，逐例实测，不伪造单调性。 |
| GA/SA具有全局探索优势，因此应默认使用 | 第一轮先实现多初解与VNS。只有同预算对比支持后，才加入其他优化器。 |

官方 README、docs 和源码之间也存在历史文本差异：`docs/核内调度算法.md` 中部分表格把三个“步骤”称为三个“问题”，并出现旧式 ALLOC/FREE、offset 与毫秒级运行时间描述。赛题原文和当前 README 明确本题三个问题分别对应场景A、场景B和L2；Step3 将内存抽象为可拆分容量额度。若论文引用运行复杂度/速度，应使用当前源码与实测 profiler，不引用旧示例数字。

输入边格式的差异也需注明：原文限定二部边，当前官方校验额外接受直接 op→op 边。本轮原始数据审计使用官方校验，并在内部图保留直接依赖；不会自行生成或修改原始数据来利用这一差异。
