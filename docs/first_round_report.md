# 第一轮交付说明

本轮范围为工程实现和代表算例验证。全部100例完成结构审计；实际求解只覆盖6例×3个问题×2种核数，未执行100例正式优化。竞赛参数尚未冻结，未声称达到全局最优或证明国赛竞争力。

## 算法实现

真实选择目标为 `(official makespan, added_copy_bytes)` 字典序。四类种子分别面向负载、亲和度、关键路径和双Pipe平衡，每类有多个工作量粒度；ready-list分配考虑前驱可用时间、通信和同核复用。整图候选只在规模阈值内常规尝试，大图保留不可行时的紧急兜底。

VNS实现核移动、核间交换、独立块换序、合并、重块分裂、边界移动、强连接块联合放置、关键路径移动。每轮生成去重候选，经便宜估计排序只将top-K交给官方评估；仅接受真实目标改善。当前实现是变邻域下降，没有随机接受劣解或精确优化模块。

默认预算120秒/最多36次评估，大图另限制26次。时间是官方调用之间检查的软截止，进行中的调用可超时。只在尝试四个种子族后考虑转入VNS，种子阶段时间比例为45%。内存和Cache估计记录用于诊断，默认权重均为0；没有证据将其写成已经有效的专项优化。

## 正确性

- pytest：41项通过；覆盖输入/DAG/分区完整唯一/核顺序/序列化、确定性、缓存失效与三个官方评估器。
- minimal regression：问题1/2/3均为6 cycles、额外搬运0。
- 增加了问题2/3局部FIFO与跨核依赖形成全局等待环的拒绝测试。仅有商图无环不足以保证官方场景B可执行。
- 全部100例通过GraphData读取与官方输入验证：原图766～38,666个操作，总计699,118个。详见 `results/dataset_audit.csv`。
- Windows下已实际验证包安装、从项目外目录启动以及官方CLI；Linux尚未实测。路径采用pathlib，核心无GPU和第三方求解器依赖。

## Benchmark与当前方案

完整逐例 Baseline / Multi-seed / VNS Makespan、改进率、Added Copy及累计时间，见 [第二轮实验表](../results/development_v2/REPORT.md)。原始108行指标保存在同目录 `benchmark.csv`，每组方案和官方CLI结果均单独保存。Baseline和Multi-seed为同一次VNS运行的前序检查点，是嵌套阶段消融，不是各自获得完整120秒预算的独立求解器对决。

保留第一轮 `development_v1` 与第二轮 `development_v2` 的manifest和源码快照。版本比较记录在第二轮目录；不要将逐例版本最优拼成新的统一算法成绩。第一轮另有剖析和单核进程并发，跨版本墙钟时间不能用来作严格算法加速结论。

第二轮36组中，VNS相对Baseline平均逐组Makespan降低18.79%，相对Multi-seed平均降低2.38%，其中25组有严格Makespan改善。最终36组均通过独立CLI，真实官方调用943次，运行内缓存命中11次，不可执行候选0；另有专门不可执行输入测试，0并不表示所有可能方案都可行。累计求解时间为各任务时间之和1795.76秒，官方调用累计1704.81秒；实际单组最大128.11秒，体现软截止的超时。

当前开发集优先保留第二版四族多粒度初解+VNS：相对第一版平均逐组Makespan降低4.45%，16组改善、16组持平、4组回退。回退均在case_019：P1/N2从40,506升至44,825（+10.66%），P1/N4从26,739升至27,204，P2/N2和P3/N2均从37,836升至38,711。不能把该组合称作逐例最强。完整对比见 `results/development_v2/version_comparison.csv`。

单核基准来自独立官方单核流程；第二轮复用官方源码指纹一致的第一轮单核结果，并保存来源声明。问题1/2图表采用逐例单核/多核比值再求均值。问题3同时提供独立优化结果对照和同一P3方案关闭L2的对照，后者用于分离方案变化和缓存影响。未实验的N=3/5不补造数据。

相对官方单核的平均加速比：问题1两核1.541、四核2.416；问题2两核1.723、四核2.891。同方案L2平均加速比两核1.000072、四核1.004360，实际收益有限；最高命中率约35.62%也不能直接解释为同幅度的Makespan改善。

## 瓶颈与下一步优化

`results/development_v1/profile_case050_p2.txt` 的6次调用剖析中，12.503秒总耗时有11.968秒在官方评估适配调用，约95.7%；官方Task构建累计10.686秒、Step3模拟累计7.993秒（相互包含，不可相加）。Step3完成性检查产生约3,696万次生成器调用。官方代码保持不变。

下一轮首先改进候选排序和评估预算分配，分析哪个邻域实际产生收益，提升每次昂贵评估的价值。保留回退案例作回归门槛，扩大到10～20例开发集后再冻结配置。内存/缓存启发式需要独立消融；目前相关性观测不足以证明加入目标权重会提升Makespan。只有这些实验仍显示明确搜索停滞且存在可负担的小窗口时，再比较局部精确搜索或其他方法，当前没有证据直接引入GA。

逐候选记录显示：N1/N2分别产生50/23次真实目标改善，N4/N5产生13/8次；N3的78条评估记录无改善，N7只有2条、N8只有13条且均无改善。这些是含缓存命中的记录数，不是独立实验样本。下一轮可优先比较缩减N3预算与调整邻域次序；N7/N8样本不足，不能据此断言无效。详细计数见 `neighborhood_diagnostics.json`。问题2/3内存与Spill的跨例Pearson约0.85/0.84，但仍混杂规模因素，不能直接启用权重。

本轮没有完成A0～A4完整消融、CP-SAT/SA/GA、Linux实测和100例×N=2/3/4/5正式实验。`competition.yaml`只是研究预算预设。
