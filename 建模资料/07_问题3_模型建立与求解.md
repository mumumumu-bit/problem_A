# 问题三：共享 L2 Cache 资源下的多核切图与调度模型

---

## 1. 问题分析

### 【问题分析】

**研究对象**：在问题 2（场景 B）的基础上，硬件平台新增一个所有核心共享的**只读 L2 FIFO Cache**。

**L2 Cache 参数**：

| 参数 | 取值 |
|------|------|
| 容量 | 1,048,576 bytes（1 MB） |
| 命中带宽 | 250 bytes/cycle（独立于 DDR 带宽） |
| 替换策略 | FIFO（先进先出，命中不刷新顺序） |
| 查询范围 | 仅 COPY_IN 操作 |
| 缓存条件 | 单个 tensor ≤ 1 MB（超过则不缓存） |

**核心任务**：在场景 B + L2 Cache 条件下设计切图与调度算法，使得 Makespan 最小化，并最大化 Cache 命中率。

**问题 3 与问题 2 的关系**：
- 问题 3 是问题 2 的**严格超集**：问题 2 的方案在问题 3 中直接可用（Cache 可能全部 miss），因此问题 3 的最优 Makespan ≤ 问题 2 的最优 Makespan
- 优化增量来源于**利用 Cache 减少 DDR 带宽竞争**——命中的 COPY_IN 不进 DDR 带宽池，使其他在途 DDR 搬运获得更多带宽、更快完成

**Cache 带来新维度**：
- 切图方案决定了"哪些核心需要读取哪些 DDR 输入"——如果多个核心都需要同一个 DDR tensor，则会产生多次 COPY_IN
- 这些 COPY_IN 在时间上的**聚集程度**决定了 Cache 命中率：时间越接近，后发的 COPY_IN 越可能在 Cache 中找到前发的数据
- 但 COPY_IN 的时间又取决于调度方案和多核竞争，形成循环依赖

### 【建模目标】

对每个计算图，输出 `node_to_subgraph` 和 `core_schedules`，使得问题 3 评估器下的 Makespan 最小化，同时提高 Cache 命中率。

**需要新增的建模能力**：
1. 预估给定切图+调度方案下的 Cache 命中率
2. 量化 Cache 命中节省的 DDR 带宽对 Makespan 的贡献
3. 将 Cache 友好性嵌入 GA 搜索引导

### 【问题抽象】

将问题抽象为**带两级存储层次（DDR + L2 Cache）的多核 DAG 联合合并-调度-缓存优化问题**。

核心新约束是 Cache 的 FIFO 容量和访问行为。Cache 状态是全部 COPY_IN 历史的函数，而 COPY_IN 的发射时间又依赖于方案，构成闭环。

**建模策略**：不在 GA 搜索中精确模拟 Cache 行为（代价太高），而是建立**简化的 Cache 命中率预估模型**，将其作为适应度奖励项，引导 GA 向"Cache 友好"的方向搜索。

## 2. 模型假设

### 【模型假设】

**假设 1~8**：继承问题 1（假设 1~5）和问题 2（假设 6~8）的全部假设。

**假设 9（Cache 命中率可近似估计）**：FIFO Cache 的命中率可以通过"按预估时序模拟 FIFO 队列"来近似估计，而不必运行完整多核仿真。

- **合理性**：Cache 的 FIFO 行为是确定性的（给定 COPY_IN 序列和发射时间）。虽然精确的 COPY_IN 发射时间需要完整离散事件仿真，但**相对时间序**是稳定的（由核内 op 的顺序和大致执行周期决定）。使用预估时序进行 FIFO 模拟，得到的命中率趋势与真实命中率高度正相关——对 GA 的"引导方向"目的已足够。
- **作用**：为 GA 适应度提供 Cache 奖励项的快速计算。

**假设 10（Cache 命中主要来自多核共享输入）**：对 Cache 命中率贡献最大的场景是：同一 DDR tensor 被多个核心的 COPY_IN 在时间上接近地访问。

- **合理性**：赛题计算图中 DDR 输入 tensor 数量有限，且每个 DDR 输入只搬入一次（赛题保证）。多核方案中若多个核心需要同一 DDR 数据，才会产生对同一 tensor 的多次 COPY_IN。核内重复的 COPY_IN（因 SPILL 产生）访问的是内部 backing tensor，id 不同。
- **作用**：将 Cache 命中率优化的焦点缩小到"跨核共享输入的访问时序"。

**假设 11（COPY_IN 的预估发射时间可由简化时序估算）**：每个 COPY_IN 的预估发射时间 ≈ 该 Task 的激活时刻 + 到该 COPY_IN 为止的累积 op cycles（按独占执行简化计算）。

- **合理性**：虽然实际执行中多核和多 Pipe 的并行会改变精确时间，但"哪些 COPY_IN 发生在前、哪些在后"的相对顺序是基本正确的。FIFO Cache 的命中判定主要取决于**相对顺序**而非绝对时间。
- **作用**：提供 COPY_IN 序列的预估时间戳，用于 FIFO 模拟输入。

## 4. 数学模型建立

### 4.1 模型构建思想

问题 3 的模型在问题 2 的 GA 框架基础上，新增**Cache 行为简化模型**作为第三个问题特化模块（前两个为代理模型和存储峰值估计器）。

整体思想是：将 Cache 命中率作为 GA 的**奖励信号**而非约束，通过适应度奖励引导搜索方向。这避免了将 Cache 建模为精确约束的困难，同时保持了优化方向的正确性。

**三层适应度结构**（逐层叠加）：

```
问题1: F = f(Makespan, 搬运量)
问题2: F = f(Makespan, 搬运量, 溢出惩罚)
问题3: F = f(Makespan, 搬运量, 溢出惩罚, Cache奖励)
```

### 4.2 数学表达

#### 4.2.1 FIFO Cache 简化模拟器

**输入**：
- 所有跨核 COPY_IN 操作的列表 $\mathcal{L} = \{(o_k, t_k, s_k)\}$，其中 $o_k$ 是 COPY_IN 操作，$t_k$ 是来源 DDR tensor 的 logical id，$s_k$ 是 tensor 大小
- 每个 $o_k$ 的预估发射时间 $\hat{t}_k$

**输出**：预估命中字节数 $\hat{\mathcal{H}}_{\text{bytes}}$、总访问字节数 $\mathcal{M}_{\text{total}}$、预估命中率 $\hat{\mathcal{H}}$。

**算法**：

1. 按 $\hat{t}_k$ 升序排列所有 COPY_IN，得到有序序列
2. 初始化空 FIFO 队列 $\mathcal{Q} \leftarrow []$，$\mathcal{Q}_{\text{used}} \leftarrow 0$
3. 对序列中每个 COPY_IN $(o_k, t_k, s_k)$：
   - **若 $s_k > C_{\text{cache}}$**（单个 tensor 超过 Cache 容量）：不缓存 → 判定 miss，$\mathcal{M}_{\text{bytes}} \leftarrow \mathcal{M}_{\text{bytes}} + s_k$
   - **否则**：
     - 查询 $\mathcal{Q}$ 中是否已存在 $t_k$：
       - **命中**：$\hat{\mathcal{H}}_{\text{bytes}} \leftarrow \hat{\mathcal{H}}_{\text{bytes}} + s_k$（不修改 FIFO 顺序，不占带宽池）
       - **未命中**：$\mathcal{M}_{\text{bytes}} \leftarrow \mathcal{M}_{\text{bytes}} + s_k$；将 $(t_k, s_k)$ 插入 $\mathcal{Q}$ 队尾，$\mathcal{Q}_{\text{used}} \leftarrow \mathcal{Q}_{\text{used}} + s_k$
     - **淘汰**：若 $\mathcal{Q}_{\text{used}} > C_{\text{cache}}$，从队首逐项移除直至 $\mathcal{Q}_{\text{used}} \le C_{\text{cache}}$
4. 输出：
   $$\hat{\mathcal{H}} = \frac{\hat{\mathcal{H}}_{\text{bytes}}}{\hat{\mathcal{H}}_{\text{bytes}} + \mathcal{M}_{\text{bytes}}}$$

**预估发射时间 $\hat{t}_k$ 的计算**：

对于核心 $c$ 上的 COPY_IN $o_k$，其预估发射时间为：

$$\hat{t}_k = T_{\text{activate}}(c) + \sum_{o \in \text{ops\_before}(o_k, c)} \frac{c_o}{2}$$

其中：
- $T_{\text{activate}}(c)$ 是核心 $c$ 的预估激活时刻（取所有跨核前驱 COPY_OUT 预估完成时间 + $t_{\text{cross\_copy}}$ 的最大值）
- $\sum c_o / 2$ 表示假设两条计算流水线（M 和 V）各承担一半负载时的等效时间

#### 4.2.2 扩展适应度函数

$$\mathcal{F}_{\text{C}}(\mathbf{x}) = \frac{1}{\mathcal{T}_{\text{C}}} \cdot \left(1 - \lambda_1 \cdot \frac{\mathcal{D}_{\text{C}}}{\mathcal{D}_{\text{orig}}} - \lambda_2 \cdot \mathcal{P}_{\text{spill}}^{\text{total}} + \beta \cdot \hat{\mathcal{H}}\right)$$

其中：
- $\mathcal{T}_{\text{C}}$：问题 3 评估器 Makespan
- $\lambda_1, \lambda_2$：搬运量惩罚和溢出惩罚权重（同问题 2）
- $\beta$：**Cache 命中率奖励系数**（问题 3 新增）
- $\hat{\mathcal{H}}$：FIFO Cache 简化模型的预估命中率

**$\beta$ 的物理含义**：

Cache 命中的收益体现为"不占用 DDR 带宽"。若命中率为 $\hat{\mathcal{H}}$，则约 $\hat{\mathcal{H}}$ 比例的 COPY_IN 字节经由 Cache 带宽（250 B/cycle）服务而非 DDR 带宽（60 B/cycle），释放了 DDR 带宽给其他搬运。

从 DDR 带宽释放角度近似估计：命中率为 $\hat{\mathcal{H}}$ 时，DDR 带宽平均竞争程度降低约 $\hat{\mathcal{H}} \cdot (B_{\text{cache}} / B) \approx \hat{\mathcal{H}} \cdot 4.2$ 的相对量级。取 $\beta = 0.10$，意味着 100% 命中率可提供约 10% 的适应度加成。

#### 4.2.3 Cache 友好的切图引导

在初始种群生成中，新增**Cache 感知策略**（占种群 20%）：

对图结构分析中识别的"多消费者 DDR 输入"（同一个 DDR tensor 被多个核心上的 op 消费），在切图时将这些消费者尽量归入**拓扑深度相近**的子图，使它们的 COPY_IN 在时间上聚集，提高 Cache 命中机会。

具体做法：
1. 识别所有 DDR tensor 及其所有消费者 op
2. 对消费者数 > 1 的 DDR tensor，将其消费者所在的子图归入同一核心或深度相邻的核心
3. 通过亲和度矩阵加权实现（共享 DDR 输入的 op 亲和度更高）

### 4.3 模型解释

| 模型元素 | 问题 3 特有含义 |
|----------|---------------|
| FIFO Cache 模拟器 | 在不运行完整多核仿真的前提下，预估 Cache 命中率——核心创新点 |
| 适应度奖励项 $\beta \cdot \hat{\mathcal{H}}$ | 量化"Cache 友好性"的收益：命中率越高，等效 Makespan 越小 |
| 预估发射时间 $\hat{t}_k$ | 用简化时序（无并行竞争）近似真实 COPY_IN 的时间序——牺牲精度换取速度 |
| Cache 感知切图 | 在初始解中引导共享输入的时间局部性——"预热"GA 的搜索起点 |
| 问题 3 相对问题 2 的加速比 | 论文核心对比指标：$\frac{\mathcal{T}_{\text{无L2}}}{\mathcal{T}_{\text{有L2}}}$ |

## 5. 模型求解

### 【求解方法】

继承问题 2 的 GA 框架和存储峰值估计器，新增 FIFO Cache 简化模拟器作为第三层问题特化模块。

**三层特化模块的调用时序**：

```
个体解码
    │
    ▼
存储峰值估计器 (问题2) → P_spill
    │ (通过阈值检查)
    ▼
FIFO Cache模拟器 (问题3新增) → Ĥ
    │
    ▼
代理模型预筛选
    │
    ▼
问题3评估器 → T_C, D_C, 真实命中率 H_real
    │
    ▼
适应度: F_C(已知 T_C, D_C, P_spill, Ĥ)
```

**后期可选用 $\mathcal{H}_{\text{real}}$ 替代 $\hat{\mathcal{H}}$**：当 GA 迭代足够多代后（如 50 代后），代理模型积累的评估数据中已包含真实命中率，可逐步用真实值替代估计值计算适应度，提升精度。

### 【求解流程】

```
输入: 计算图 G, 核心数 N, config.txt (含 [problem_3] Cache参数)
输出: node_to_subgraph, core_schedules

Step 0: 图预处理（同问题2）
    + 额外: 识别多消费者DDR tensor（消费者分布于不同当前核心的）
    + 计算"DDR共享亲和度": 共享同一DDR输入的op间亲和度加权

Step 0.5: Cache相关预计算
    - 对每个DDR tensor，标记其所有消费者op的核心归属（取决于切图）
    - 构建"跨核COPY_IN预估列表"数据结构

Step 1: 初始种群生成（P_size = 50）
    - 策略1 (40%): 问题2的粗切分（150~400区间）
    - 策略2 (40%): 问题2的粗切分（同上）
    - 策略3 (20%): ★Cache感知切分★
      - 沿关键路径粗切分
      - 将共享同一DDR输入的消费者op归入相邻深度区间
    - 每种切分调用问题3评估器

Step 2: 训练代理模型（特征集增加: 预估命中率 Ĥ）

Step 3: GA迭代
    For g = 1 to G_max:
        a) 选择、交叉、变异
        b) 新个体 → 存储峰值估计器
        c) 溢出检查: 若 P_spill > T_thresh → 跳过评估
        d) FIFO Cache模拟器 → 计算 Ĥ
        e) 代理模型预筛选
        f) 问题3评估器 → T_C, D_C, H_real
        g) 适应度:
            前期(g ≤ 50): F = (1/T_C)*(1 - λ1·D_C/D_orig - λ2·P_spill + β·Ĥ)
            后期(g > 50): F = (1/T_C)*(1 - λ1·D_C/D_orig - λ2·P_spill + β·H_real)
        h) 精英保留 + 截断选择
        i) 收敛判定

Step 4: 输出最优方案
```

### 【计算步骤】

**步骤 0.5：Cache 相关预计算**

1. 遍历所有 DDR tensor，获取其所有消费者 op
2. 对消费者数 > 1 的 DDR tensor，标记为"可共享输入"
3. 预计算各 DDR tensor 的 size（用于 FIFO 模拟中判断是否 > 1MB 不缓存）

**步骤 1：Cache 感知初始切分策略**

```text
输入: 计算图 G, 拓扑序 seq, 核心数 N
输出: 初始切分方案

1. 识别可共享 DDR 输入集合 S = {t | pos(t)=DDR, consumers(t)>1}
2. 对每个 t ∈ S:
   - 收集 t 的所有消费者 op
   - 在亲和度矩阵中，将这些消费者两两之间的亲和度增加 w_share * s_t
     (共享数据越大，商业和度越高)
3. 对加权后的亲和度矩阵进行层次聚类
4. 按聚类结果切分子图（保证聚类内 op 拓扑连续）
5. 列表调度生成 core_schedules
```

**步骤 3d：FIFO Cache 模拟器的在线调用**

每次 GA 评估前，对当前个体执行：

1. 解码得到每核的子图序列和 `core_schedules`
2. 推算每个核心上 COPY_IN 的预估时间 $\hat{t}_k$：
   - 在问题 2 的简化时序估算基础上（已由存储峰值估计器部分完成）
   - 增加 DDR COPY 搬运时长估算（数据量 / 60 B/cycle，假设无竞争时的下界）
3. 按 $\hat{t}_k$ 排序所有 COPY_IN
4. 运行 4.2.1 节的 FIFO 模拟
5. 输出 $\hat{\mathcal{H}}$

**步骤 3f：评估器特殊配置**

问题 3 的评估器 `multicore_cut_evaluate_problem_3.py` 额外读取 `config.txt` 的 `[problem_3]` 段。运行命令：

```bash
python code/multicore_cut_evaluate_problem_3.py data/<case>.json --config data/config.txt
```

评估器输出额外包含 `cache_hit_rate`、`cache_hit_bytes`、`cache_miss_bytes` 等 Cache 统计字段。

## 7. 三个问题的模型演进总结

```
问题1（场景A）         问题2（场景B）          问题3（场景B+L2 Cache）
    │                      │                        │
GA编码+适应度(Makespan)  +存储峰值估计器          +FIFO Cache模拟器
    │                      │                        │
F = 1/T * (1-λ₁·搬运)   F = 1/T * (1-...-λ₂·溢出)  F = 1/T * (1-...-λ₂·溢出+β·命中率)
    │                      │                        │
细粒度切分               粗粒度切分                粗粒度+Cache感知切分
(50~150 op/子图)        (150~400 op/子图)         (150~400 op/子图)
```

**模型演进的核心逻辑**：
- 问题 1 解决"并行与通信的权衡"（基本问题）
- 问题 2 在并行+通信的基础上增加"存储约束"（第二维度）
- 问题 3 在以上三维基础上增加"Cache 层次优化"（第三维度）
- 每一层都是在前一层框架上的**增量扩展**，而非推倒重来——这体现了建模的系统性和可扩展性
