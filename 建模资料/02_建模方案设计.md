# 建模方案设计 —— 《通用神经网络处理器下的多核调度问题》

---

## 一、问题建模需求分析

### 【问题 1 建模需求】

**建模目标**：设计一种多核切图与调度算法，在场景 A（每子图一 Task，Task 间需切换等待）下，对任意给定的神经网络计算图，产生 `node_to_subgraph` 和 `core_schedules` 方案，使得全局 Makespan 最小化、额外数据搬运量尽量低。

**研究对象**：计算图 DAG 中非 COPY 操作节点（约 43~1654 个）的**子图归属划分**与**核心调度排序**。

**需要刻画的关系**：
1. **切图粒度与通信开销的关系**：子图越小 → 并行度越高 → 但跨子图通信（经 DDR 中转的 COPY_IN/COPY_OUT）和 Task 切换等待（同核 100 cycle / 跨核 1000 cycle）越多。需要量化"切一刀"引入的代价。
2. **核心分配与负载均衡的关系**：子图在不同核心上的分布决定了各核执行时间的长短，关键路径上的核心负载直接决定 Makespan 下界。
3. **子图顺序与依赖等待的关系**：同核子图执行顺序若违反数据依赖（即使已在不同子图），会导致额外的等待时间。评估器会拒绝非法顺序。

**预期结果**：
- 对每个计算图，输出合法的 `node_to_subgraph` 和 `core_schedules`
- 正文给出 1~5 核的平均加速比折线图
- 附录逐用例列出 Makespan 与额外数据搬运量

**建模重点**：
- 切图策略：如何基于图拓扑结构确定最优子图数量和边界
- 调度策略：如何将子图分配到核心并排序以最小化关键路径
- 模型需要处理**核数可变**（2~5），即须支持可配置的并行度

---

### 【问题 2 建模需求】

**建模目标**：在场景 B（每核合并为一个 Task，同核子图间数据可片上直传）下，设计切图与调度算法。核心新增约束：同核子图合并后，片上 L1/UB 容量可能不足，触发核内调度算法的自动换入换出（Spill），大幅增加 DDR 搬运和延迟。

**研究对象**：除了子图归属和调度，还需要关注**每核合并后的核内张量驻留峰值**——这决定了是否溢出、溢出多少。

**需要刻画的关系**：
1. **子图合并的"边际收益递减"规律**（赛题官方提示）：两个子图合并后的执行时间通常小于各自独立执行之和（收益来自头尾搬运被流水掩盖 + 通信成本降低）；但当子图规模超过一定阈值后，片上容量不足导致大量溢出，产生**负收益**。
2. **切图边界与片上驻留量的关系**：切图边界处的张量若在跨核通信中通过 DDR 中转（问题 1），则在场景 B 中若同核则可保留在片上。这引入了"张量生命周期管理"的新维度。
3. **跨核通信延迟（500 cycle）与核内溢出搬运的权衡**：将更多子图放在同核可能减少跨核通信，但增加溢出风险。

**预期结果**：
- 正文给出场景 B 下 1~5 核平均加速比折线图
- 附录逐用例列出 Makespan 与额外数据搬运量

**建模重点**：
- 需要**预估核内存储峰值**——不能完全依赖评估器逐次仿真
- 需要设计**切图粒度的自适应控制**——根据图规模和硬件容量动态调整
- 考虑张量生命周期的空间-时间权衡

---

### 【问题 3 建模需求】

**建模目标**：在问题 2 基础上增加共享只读 L2 Cache（1 MB / 250 bytes/cycle），研究其对多核调度的影响。Cache 命中可节省 DDR 带宽（不占 DDR 带宽池），这使得多核并发时的 DDR 带宽竞争压力减轻。

**研究对象**：除问题 2 的全部要素外，还需考虑**哪些 COPY_IN 访问可被 Cache 服务**——这取决于跨核共享数据的访问时序和 Cache 的 FIFO 替换行为。

**需要刻画的关系**：
1. **切图方案 → Cache 命中率的关系**：若多个核心都需读取同一 DDR 输入数据，当它们的 COPY_IN 在时间上相近时，后发者可能命中 Cache。切图时若将共享同一输入的节点分散到不同核，则需多次 COPY_IN → Cache 复用机会增多。
2. **Cache 命中 → DDR 带宽释放 → 多核并行提速**：Cache 命中率越高，DDR 带宽竞争越少，在途搬运的公平份额带宽越大，单个搬运越快。
3. **Cache 容量有限（1MB）→ 超过容量的数据不缓存**：并非所有共享数据都能受益于 Cache。

**预期结果**：
- 正文给出无 L2 vs 有 L2 对比曲线 + 相对加速比
- 附录逐用例列出双配置的 Makespan、搬运量、Cache 命中率

**建模重点**：
- 需要**近似建模 Cache 行为**以指导优化（不需要精确模拟，但需定性指导）
- 考虑切图方案对 Cache 命中率的"结构影响"（共享数据的访问模式由切图决定）

## 二、候选建模方案

### 【方案 A】基于图拓扑分析的贪心构造 + 局部搜索

**模型思想**：
将切图与调度问题解耦为两阶段：第一阶段基于图拓扑特征（深度、关键路径、张量生命周期）进行贪心切图；第二阶段对切图结果进行调度优化，最后通过局部搜索迭代改进。

**数学方法**：

1. **图分析与特征提取**：
   - 计算每个 op 的拓扑深度（ASAP/ALAP）、关键路径标识
   - 计算每个 tensor 的生产者-消费者跨度和字节大小
   - 构建算子亲和度矩阵（共享 tensor 越多 → 亲和度越高）

2. **贪心切图（基于拓扑区间的连续划分）**：
   - 将 ops 按拓扑序排列
   - 在满足"每子图不超过一定规模"和"不切断高亲和度边"的原则下贪心切分
   - 子图规模的上下界根据 L1/UB 容量自适应设定

3. **调度（列表调度 + 关键路径优先）**：
   - 以子图为调度单元，基于子图间的 DAG 依赖关系
   - 优先级规则：子图所在关键路径长度 → 子图计算量 → 子图输入数据量
   - 贪婪地将就绪子图分配到最早可用的核心

4. **局部搜索改进**：
   - 邻域操作：合并相邻子图、拆分过大于图、交换子图核心分配
   - 接受能使 Makespan 降低的移动

**适用原因**：
- 计算图是 DAG，拓扑分析自然适用
- 评估器本身按拓扑序处理，贪心策略与核内调度算法有内在一致性
- 局部搜索可为后续更高级优化提供初始解

**优点**：
- 结构清晰，每一步都有明确的数学含义，**论文表达效果好**
- 可解释性强：为什么这样切、为什么这样调度都可说清楚
- 实现难度适中，不依赖外部优化库
- 计算效率高，可作为元启发式方法的初始解

**不足**：
- 贪心策略可能陷入局部最优
- 切图与调度的解耦可能丢失联合优化的机会
- 对图结构多样性的适应能力有限

### 【方案 B】基于遗传算法（GA）的元启发式优化

**模型思想**：
将切图与调度方案编码为染色体，以评估器输出的 Makespan 作为适应度，通过选择、交叉、变异等遗传操作在解空间中搜索最优方案。

**数学方法**：

1. **个体编码**：采用双染色体编码
   - 染色体 1（切图编码）：长度为 N_op 的整数数组，表示每个 op 所属子图的 rank 值，通过解码（按 rank 分组 + 拓扑序约束）得到实际 `node_to_subgraph`
   - 染色体 2（调度编码）：子图的优先级列表，配合列表调度算法生成 `core_schedules`

2. **适应度函数**：`fitness = 1 / Makespan`（或加入额外搬运量的惩罚项）

3. **遗传操作**：
   - 选择：锦标赛选择 / 轮盘赌
   - 交叉：基于拓扑约束的单点/双点交叉（保证子代仍对应合法 DAG 划分）
   - 变异：随机改变某个 op 的子图归属（合并到邻居子图或独立为新子图）

4. **约束处理**：交叉和变异后需修复非法个体（如子图依赖成环），通过投影算子恢复到合法空间

5. **精英保留 + 自适应变异率**

**适用原因**：
- 评估器是黑箱，天然适合无梯度优化方法
- GA 对组合优化问题的编码灵活，适合离散决策空间
- 能同时探索切图和调度两个维度的耦合

**优点**：
- 全局搜索能力强，理论上可逼近全局最优
- 不依赖问题的可微性，适用于黑箱评估
- 易于并行化（种群中多个个体可并行评估）
- 在数学建模竞赛中是成熟且被广泛接受的方法

**不足**：
- 评估成本高：适应度计算需要完整仿真，种群 × 代数的评估次数可能非常大
- 编码-解码的约束处理复杂：需要精心设计以保证解的合法性
- 收敛性和参数敏感：交叉率、变异率、种群大小等需要调试
- 论文中需要为"为何选 GA"提供充分论证，避免被质疑"随意套用"

### 【方案 C】基于图神经网络（GNN）的代价预测 + 启发式搜索

**模型思想**：
训练一个图神经网络模型，以计算图的局部子结构为输入，预测该子结构的"核内执行代价"（执行时间、溢出概率、Cache 命中倾向等）。将该预测模型作为快速代价估计器，嵌入到启发式搜索或元启发式框架中，大幅减少对真实评估器的调用次数。

**数学方法**：

1. **图表示学习**：
   - 将 op-tensor 二部图转换为异构图
   - 使用 GraphSAGE / GAT 对每个 op 节点生成嵌入向量（编码其局部拓扑、操作类型、tensor 大小分布）
   - 通过读出（readout）函数生成子图级或全图级表示

2. **代价预测器**：
   - 输入：子图的计算图片段 + 子图规模统计量
   - 输出：预测的核内执行时间、核内存储峰值、可能的 SPILL 次数
   - 损失函数：预测值与真实评估器输出的 MSE

3. **嵌入搜索框架**：
   - 将训练好的预测器作为快速适应度近似函数
   - 在 GA 或蒙特卡洛树搜索（MCTS）中，用预测器筛选候选解，仅对最有希望的候选调用真实评估器验证

**适用原因**：
- 100 个计算图提供了丰富的训练数据（每个图的不同切分方案产生不同的子图结构）
- GNN 天然适合处理图结构数据，能捕捉拓扑特征的内在规律
- 快速代价估计是解决评估瓶颈的关键

**优点**：
- 大幅减少评估次数（预测器替代大部分仿真）
- 能学习到人工难以显式编码的图结构-代价映射
- 在建模竞赛中体现了多方法融合的前沿性创新

**不足**：
- **实现复杂度极高**：训练 GNN 需要大量标注数据（需预先生成成千上万个子图评估结果作为训练集）
- 数据标注成本极高但可以离线完成；问题 2/3 的评估更慢
- 泛化性存疑：在一种图分布上训练的模型可能在其他拓扑结构上表现不佳
- 论文中需要大量篇幅解释 GNN 的设计与训练，可能喧宾夺主
- 赛题给定的 100 个用例可能不足以支撑 GNN 训练

### 【方案 D】基于分层分解的多阶段优化框架

**模型思想**：
将问题按"从粗到细"的层次分解：第一层进行粗粒度的图结构分析和关键路径识别；第二层在关键路径引导下进行初始切图和核心分配；第三层在局部范围内进行精细调整。每一层使用适合该粒度的方法，层间通过反馈迭代协调。

**数学方法**：

1. **第一层——全局图分析**：
   - 计算操作的 ASAP（As Soon As Possible）和 ALAP（As Late As Possible）时间
   - 识别关键路径（critical path）上的操作序列
   - 计算每个 op 的"并行潜力" = ALAP - ASAP
   - 构建操作的"层级分组"（同一层级内操作可并行）

2. **第二层——粗粒度切图与调度**：
   - 基于关键路径和层级分组，确定初始切分点和子图数
   - 使用**整数规划（ILP）或约束满足（CSP）**对粗粒度子图进行优化分配
   - 由于子图数控制在较小范围（如 10~20 个），ILP 可在合理时间内求解

3. **第三层——精细调整**：
   - 对每个子图内部进行局部拓扑序优化
   - 对于问题 2/3，额外检查每核合并后的存储峰值预估
   - 在子图边界处进行微调：将边界 op 从一个子图移动到相邻子图，观察代价变化

4. **跨层反馈**：
   - 第三层的评估结果反馈到第二层，调整粗粒度的切分参数
   - 迭代至收敛或达到时间预算

**适用原因**：
- 赛题官方明确指出了多个优化方向（通信成本、并行度、数据重复读取、Cube/Vector 并行、子图合并负收益），分层处理可以逐层针对
- 图结构具有天然的层级特征（神经网络通常按层组织），分层方法贴合问题本质
- 在某些层使用精确方法（ILP），在另一些层使用启发式，实现了精度与效率的折中

**优点**：
- **数学建模深度最高**：综合运用图论、整数规划、启发式搜索等多种数学工具
- 结构清晰，每层问题规模可控
- ILP 部分有严格的优化理论支撑，论文中可给出形式化模型
- 适合在论文中展示"问题分解 → 逐层求解 → 全局协调"的完整建模思路

**不足**：
- ILP 的规模受限于子图数量（子图太多时 ILP 难以求解）
- 层间协调需要精心设计的接口
- 实现工作量较大，需要在多个方法之间切换
- 如果某个中间层的假设不成立（如 ILP 的简化假设），可能导致次优解

### 【方案 E】基于模拟退火（SA）的单解法方案

**模型思想**：
将整个切图+调度方案作为一个完整状态，定义邻域扰动操作（随机移动一个 op 到相邻子图、随机交换两个核心上的子图等），使用模拟退火算法在解空间中搜索，以 Makespan 为目标，通过温度衰减平衡探索与利用。

**数学方法**：

1. **初始解构造**：使用方案 A 的贪心方法生成初始合法解
2. **邻域定义**（多类型扰动混合）：
   - 类型 1——边界移动：将子图边界上的一个 op 移动到相邻子图
   - 类型 2——子图合并：随机选取两个同核相邻子图合并
   - 类型 3——子图拆分：随机选取一个大于图沿拓扑中间点拆分为二
   - 类型 4——核心重分配：随机将某个子图移动到另一个核心的合法位置
3. **Metropolis 准则**：$\Delta E = \text{Makespan}_{\text{new}} - \text{Makespan}_{\text{old}}$
   - 若 $\Delta E \le 0$：接受
   - 若 $\Delta E > 0$：以概率 $e^{-\Delta E / T}$ 接受
4. **冷却策略**：$T_{k+1} = \alpha \cdot T_k$（$\alpha = 0.95\sim0.99$）
5. **重启机制**：当连续 N 步未改进时，从历史最优解重新开始

**适用原因**：
- 模拟退火是处理复杂组合优化的经典方法，有坚实的数学理论基础
- 相比 GA，SA 超参数少，易于分析和调参
- 邻域操作可直接保证解的合法性（不需要复杂的修复算子）

**优点**：
- 数学理论成熟（马尔可夫链、收敛性分析），在竞赛论文中论证充分
- 参数少、调参简单
- 实现难度较低，适合快速迭代
- 在实际工程优化中广泛应用，与华为赛题背景吻合

**不足**：
- 纯 SA 可能在复杂解空间中收敛缓慢
- 邻域设计对效果影响大，需要针对问题定制
- 单点搜索缺乏 GA 的种群并行搜索能力
- 对于 100 个不同算例，温度调度和重启策略难以统一设定

### 【方案比较分析】

1. **方案 A（贪心+局部搜索）**是最稳妥的基线，但单独使用在建模深度上可能不足。它更适合作为其他方案的**初始解构造器**或**子模块**，而非完整解决方案。

2. **方案 B（GA）**是数学建模竞赛中最常见的方法之一，在处理黑箱优化时效果好。但其"黑箱"特性在论文中需要额外论证（如何设计编码、如何保证合法性）。此外，100 个算例 × 多代种群 × 多次评估的仿真开销可能过大。

3. **方案 C（GNN+搜索）**虽然有创新性，但实现成本和学习数据需求过高，风险大。如时间充裕且团队有相关经验可尝试，但不建议作为主力方案。可作为**论文中的"探索方向"**提及。

4. **方案 D（分层分解）**数学建模深度最高，最能体现"分析问题→分解问题→逐层求解→全局协调"的完整建模能力。但实现工作量极大，需要团队分工明确。

5. **方案 E（SA）**在可解释性、理论基础和实现难度之间取得了良好平衡。作为单解法方案结构清晰，但搜索效率可能不如 GA。

## 四、推荐建模方向

### 【总体推荐】

建议采用 **"方案 A + 方案 B（或方案 E）"的混合架构**：以图拓扑分析的贪心构造器生成高质量初始解，以元启发式方法（GA 或 SA）在初始解基础上进行全局优化。具体推荐：

- **主框架**：**遗传算法（方案 B）**，负责全局搜索
- **初始解生成**：**贪心构造器（方案 A 的图分析部分）**，提供高质量初始种群
- **快速预筛选**：**代理代价估计模型**（基于图结构特征的线性/非线性回归，而非 GNN），在调用真实评估器前进行粗筛
- **层次分解思想**（方案 D）融入到 GA 的编码和约束处理设计

### 【推荐理由】

1. **问题适配性最佳**：GA 天然适合离散组合优化，能同时探索切图和调度两个耦合维度。评估器是黑箱但不能求导，GA 不需要梯度信息。

2. **数学理论基础扎实**：GA 的收敛性有 Schema Theorem 和 Markov 链分析支撑；贪心策略背后有贪心算法理论；代理模型有回归分析的统计学基础。

3. **兼顾竞赛论文要求**：
   - 图分析部分提供"数学建模"的支撑
   - GA 部分提供"优化算法"的支撑
   - 代理模型部分提供"模型创新"的支撑
   - 三者在论文中形成完整的"分析→建模→求解→验证"逻辑链

4. **可实现性可控**：GA 是成熟的算法框架，Python 实现难度适中。核心瓶颈（评估次数）通过代理模型缓解。

### 【各小问建模思路】

#### 问题 1 建模思路
```
计算图 DAG 输入
    │
    ▼
图结构分析（深度计算、关键路径提取、tensor 亲和度矩阵）
    │
    ▼
GA 初始种群生成（基于拓扑区间 + 关键路径的贪心切分 + 列表调度）
    │
    ▼
GA 迭代：交叉/变异 → 合法化修复 → 代理模型预筛选 → 真实评估器验证
    │
    ▼
输出：node_to_subgraph + core_schedules
    │
    ▼
评估：Makespan + 额外搬运量 + 加速比
```

**问题 1 特有设计**：
- 适应度中显式惩罚跨核通信（子图间边的 tensor size 加权）
- Task 切换开销在 GA 适应度中通过 Makespan 间接体现
- 代理模型需预估：核内执行时间 + Task 切换等待 + COPY 搬运时间

#### 问题 2 建模思路
```
问题 1 的方案结构（复用）
    │
    ▼
增加：每核合并后的存储峰值预估模块
    │  输入：该核子图序列的 op 与 tensor 列表
    │  方法：基于张量生命周期的驻留量上界估计（无需完整仿真）
    │  输出：预估溢出次数和溢出搬运量
    │
    ▼
GA 适应度调整：Makespan 中加入溢出搬运的时间惩罚
    │
    ▼
切图策略调整：偏好将"高亲和度但存储压力不大"的子图放在同核
```

**问题 2 特有设计**：
- **存储峰值预估是核心创新点**：需要设计一个不依赖完整仿真的快速估计方法
  - 方法：对子图序列中所有 L1/UB 张量，按拓扑序扫描其生命周期
  - 任意时刻驻留量 = 该时刻"已生产但未被末次消费"的 tensor 之和
  - 若预估峰值超过容量，按超出比例估算 SPILL 次数
- GA 中引入"存储压力惩罚项"，引导搜索向低溢出方案方向

#### 问题 3 建模思路
```
问题 2 的方案结构（复用）
    │
    ▼
增加：Cache 命中率预估模块
    │  输入：所有跨核 COPY_IN 的来源 tensor id 及其发射时间
    │  方法：基于 FIFO 行为的简化分析模型
    │  输出：预估命中次数和命中字节数
    │
    ▼
GA 适应度调整：将"命中节省的 DDR 带宽"转化为时间收益
    │  （命中 → 不占 DDR 带宽 → 其他在途搬运更快 → Makespan 减小）
    │
    ▼
切图策略调整：偏好将"共享输入的多个核心的 COPY_IN"在时间上集中
```

**问题 3 特有设计**：
- **Cache 行为简化建模**：
  - 将 Cache 抽象为容量为 C 的 FIFO 队列
  - 所有跨核 COPY_IN 按发射时间排序
  - 模拟 FIFO 插入/命中/淘汰 → 得到命中率预估值
  - 将预估命中率作为 GA 适应度的奖励项
- **实际上是问题 2 的超集**：问题 2 的方案在问题 3 中自动可用（Cache 可能全部 miss），故问题 3 的优化是在问题 2 基础上的增量改进
