# 问题一：场景 A 下的多核切图与调度模型

---

## 1. 问题分析

### 【问题分析】

**研究对象**：给定一张神经网络计算图 $G = (V, E)$（$V = O \cup T$，$O$ 为操作节点集，$T$ 为张量节点集），和多核 NPU 平台（$N$ 个同构核心，$N \in \{2,3,4,5\}$）。

**核心任务**：在场景 A（无核间同步机制）下，将计算图切分为若干子图并为每个子图分配执行核心和调度顺序，使得全局完工时间（Makespan）最小化，同时控制额外数据搬运量。

**场景 A 关键约束**：
- 每个子图独立构成一个 Task，Task 是调度和执行的最小单元
- 所有跨子图数据必须经 DDR 中转（即使两子图位于同一核心）
- 同核相邻 Task 切换需等待 $t_{\text{same}} = 100$ cycles
- 跨核前驱 Task 完成后需等待 $t_{\text{cross}} = 1000$ cycles 才能激活后继

**关键问题**：
1. 如何确定最优子图数量？切分太少则并行度不足，切分太多则通信开销和 Task 切换代价增加。
2. 如何在子图间进行依赖感知的核心分配？需要平衡负载均衡与通信减少。
3. 如何保证算法在 2~5 核范围内均能稳定输出高质量解？

### 【建模目标】

对每个输入计算图，输出切图映射 $M: O_{\text{eligible}} \to \mathbb{N}$（即 `node_to_subgraph`）和核心调度方案 $S$（即 `core_schedules`），使得评估器给出的 Makespan 最小化。

**输出结果类型**：组合优化方案（离散决策变量构成的 JSON 文件）。

### 【问题抽象】

将问题形式化为**资源约束下 DAG 划分与多处理器调度优化问题**：

**决策变量**：
- 切图映射 $M(o_i) = g_k$：每个非 COPY 操作 $o_i$ 属于子图 $g_k$
- 核心分配 $C(g_k) = c_m$：每个子图 $g_k$ 分配到核心 $c_m$
- 同核顺序 $R(c_m) = [g_{a}, g_{b}, \ldots]$：每个核心上的子图执行序列

**约束**：
1. 覆盖约束：每个 $o_i \in O_{\text{eligible}}$ 恰好属于一个子图
2. 无环约束：子图依赖图 $G_{\text{sub}}$ 必须为 DAG
3. 顺序约束：$R(c_m)$ 不违反子图间依赖偏序关系

**目标**：
$$\min \; \text{Makespan}\big(M, C, R\big)$$

其中 $\text{Makespan}(\cdot)$ 是评估器给出的黑箱函数，综合了核内调度、DDR 带宽竞争、Task 切换等待等全部因素。

**核心耦合关系**：
- 切图 $M$ 决定了 $G_{\text{sub}}$ 的拓扑和通信边（跨子图 tensor 大小）
- $C$ 和 $R$ 决定了各核心的负载和激活时序
- 三者共同通过评估器产生 Makespan，无法解耦为独立子问题

## 2. 模型假设

### 【模型假设】

**假设 1（评估器确定性）**：赛题提供的评估器对相同输入方案产生完全相同的 Makespan。

- **合理性**：核内调度算法（附录 C）和多核模拟算法（附录 D）均为确定性算法，无随机因素。
- **作用**：保证适应度函数是 $f: \mathcal{X} \to \mathbb{R}$ 的确定性映射，GA 的适应度值可复现和比较。

**假设 2（子图规模上限）**：单个子图的非 COPY op 数量不宜超过 $S_{\max} = 300$。

- **合理性**：数据分析表明，当子图过大时 L1/UB 存储压力剧增，核内 Step2 可能产生大量 SPILL。且场景 A 中同核 Task 切换会清空缓存，子图过大无助于数据复用。该假设主要用于初始化种群时的剪枝，GA 搜索过程中允许突破。
- **作用**：限制初始解的搜索空间，提高初始种群质量。

**假设 3（同核子图连续切分）**：基于拓扑排序的连续区间划分产生合法子图依赖图。

- **合理性**：若所有 ops 按拓扑序排列后，沿该序列切分为连续区间，则子图顺序自动满足依赖偏序（前区间的 op 不会依赖后区间的 op），保证子图依赖图无环。这是 stub 方案的理论基础。
- **作用**：简化初始种群生成，保证初始解合法。

**假设 4（DDR 带宽公平共享）**：多核在途 DDR 搬运按当前搬运数 $n$ 公平分配总带宽 $B$，每个搬运在 $\Delta t$ 内减少工作量为 $B \cdot \Delta t / n$。

- **合理性**：评估器明确使用该公平共享机制（附录 D）。
- **作用**：为代理模型中的 DDR 搬运时间估计提供理论基础。

**假设 5（计算图为连通 DAG）**：所有输入计算图为连通的有向无环图。

- **合理性**：赛题提供的计算图来自实际神经网络模型的分块数据流，天然满足连通性和无环性。评估器也会校验。
- **作用**：保证拓扑排序的唯一性和算法稳定性。

## 4. 数学模型建立

### 4.1 模型构建思想

问题 1 的核心是**在场景 A 约束下的 DAG 划分与多处理器调度联合优化**。

由于评估器是黑箱（无法显式写出 Makespan 关于 $M, C, R$ 的闭式表达式），不能采用传统的数学规划方法。本模型采用**进化计算框架**——将切图与调度方案编码为个体，以 Makespan 为适应度，通过遗传算法在解空间中迭代搜索。

模型由三个层次构成：
1. **编码层**：将离散决策 $(M, C, R)$ 编码为可遗传操作的染色体
2. **评估层**：通过赛题评估器（问题 1 脚本）计算 $\mathcal{T}$ 和 $\mathcal{D}$
3. **进化层**：通过选择、交叉、变异操作驱动种群向更低 Makespan 方向演化

GA 的适用性源于：切图归属和调度排序都是离散组合优化问题，GA 的交叉和变异算子自然地混合和扰动候选解，种群并行搜索避免陷入局部最优。

### 4.2 数学表达

#### 4.2.1 染色体编码

**切图编码**（长度为 $n_{\text{elig}}$ 的整数向量）：

$$\mathbf{x}_{\text{cut}} = (x_1, x_2, \ldots, x_{n_{\text{elig}}}), \quad x_i \in \{0, 1, \ldots, K_{\max}-1\}$$

其中 $x_i$ 表示按拓扑序排列的第 $i$ 个 op 的子图 cluster id。解码规则：相同 cluster id 且在拓扑序上连续的操作组成同一个子图。$K_{\max}$ 是子图数量上限，取 $\min(n_{\text{elig}}, 20N)$。

**调度编码**（长度为 $K$ 的实数向量，$K$ 为解码后的子图数）：

$$\mathbf{x}_{\text{sched}} = (y_1, y_2, \ldots, y_K), \quad y_j \in [0, 1]$$

$y_j$ 是子图 $g_j$ 的优先级。解码时采用列表调度：每次从就绪子图（前驱均已调度）中选择 $y_j$ 最大者，分配到最早可用的核心。

#### 4.2.2 适应度函数

$$\mathcal{F}(\mathbf{x}_{\text{cut}}, \mathbf{x}_{\text{sched}}) = \frac{1}{\mathcal{T}} \cdot \left(1 - \lambda \cdot \frac{\mathcal{D}}{\mathcal{D}_{\text{orig}}}\right)$$

其中：
- $\mathcal{T} = \text{evaluate\_problem\_1}(G, \text{decode}(\mathbf{x}_{\text{cut}}, \mathbf{x}_{\text{sched}}))$ 是评估器输出的 Makespan
- $\mathcal{D}$ 是评估器输出的额外数据搬运量
- $\mathcal{D}_{\text{orig}}$ 是原始计算图中的 COPY 搬运总量（归一化因子）
- $\lambda \in [0, 0.1]$ 是搬运量惩罚权重。问题 1 中 $\mathcal{T}$ 是主要目标，$\lambda$ 取较小值（如 0.05），使搬运量成为"平局打破者"而非主导目标

**说明**：若解码方案不满足合法约束（子图依赖环、重复 id 等），$\mathcal{T} = +\infty$，适应度为零，该个体在后续选择中自然淘汰。

#### 4.2.3 遗传操作

**(a) 选择——锦标赛选择**

从种群中随机选取 $n_{\text{tour}} = 3$ 个个体，保留适应度最高者进入交配池。重复直至填满交配池。

**(b) 交叉——双点交叉**

对两个父代 $(\mathbf{x}_{\text{cut}}^{(1)}, \mathbf{x}_{\text{sched}}^{(1)})$ 和 $(\mathbf{x}_{\text{cut}}^{(2)}, \mathbf{x}_{\text{sched}}^{(2)})$：

1. 随机选取两个交叉点 $p_1 < p_2 \in [0, n_{\text{elig}}]$
2. 子代切图编码：
   $$\mathbf{x}_{\text{cut}}^{(\text{child})} = \big(x_1^{(1)}, \ldots, x_{p_1}^{(1)}, x_{p_1+1}^{(2)}, \ldots, x_{p_2}^{(2)}, x_{p_2+1}^{(1)}, \ldots, x_{n_{\text{elig}}}^{(1)}\big)$$
3. 按拓扑序重新编号 cluster id（保证连续性），解码后得到新子图数 $K'$
4. 子代调度编码由父代 $y_j$ 值按子图对应关系插值生成

若交叉后出现子图依赖环（极少发生，因交叉保持了拓扑区间的基本结构），回退到父代。

**(c) 变异——多类型混合**

每次变异等概率选择以下四种之一：
1. **边界移动**（概率 0.3）：随机选取子图边界上的 op $o_i$，将其 cluster id 改为相邻子图的 id
2. **子图合并**（概率 0.2）：随机选取两个相邻子图，将它们的 cluster id 统一
3. **子图拆分**（概率 0.2）：随机选取子图，在其中间位置拆分为两个子图
4. **优先级扰动**（概率 0.3）：随机选取子图 $g_j$，将其 $y_j$ 替换为新随机值

#### 4.2.4 精英保留与收敛判定

每代保留适应度前 $e\%$（$e = 10$）的个体直接进入下一代。当连续 $G_{\text{conv}}$ 代（$G_{\text{conv}} = 15$）最优适应度无改进时，判定收敛。

### 4.3 模型解释

| 模型元素 | 实际问题对应 |
|----------|-------------|
| 染色体 $\mathbf{x}_{\text{cut}}$ | 每个非 COPY Op 到子图 id 的映射（即 `node_to_subgraph`） |
| 染色体 $\mathbf{x}_{\text{sched}}$ | 子图优先级，经列表调度转化为 `core_schedules` |
| 适应度 $\mathcal{F}$ | Makespan 的倒数（越小越好 → 适应度越大越好） |
| 交叉操作 | 将两种切图方案的"部分区段"混合，模拟不同切分策略的组合 |
| 变异操作 | 局部调整切分粒度或调度顺序，探索邻域解 |
| 精英保留 | 保证解质量不会因随机扰动而退化 |
| 收敛判定 | 避免在已无明显改进时继续无意义的搜索 |

## 5. 模型求解

### 【求解方法】

采用**遗传算法（GA）** 进行求解。

**选择 GA 的原因**：
1. 适应度函数是黑箱（评估器），无法求导，GA 只需要适应度值的相对比较，不需要梯度信息
2. 离散组合优化问题的交叉和变异操作天然适用，编码设计灵活
3. 种群并行搜索提供天然的多样性，避免局部最优
4. GA 在 DAG 调度和划分问题上有丰富的文献基础，数学理论扎实（Schema Theorem）

**关键设计决策**：
- **初始种群结构化生成**（而非完全随机）：利用图拓扑分析生成高质量种子，加速收敛
- **代理模型预筛选**：对每代所有个体先经快速回归模型预估 Makespan，仅对前 $M$ 个调用真实评估器，将单算例评估次数控制在 500~2000 次

### 【求解流程】

```
输入: 计算图 G, 核心数 N, config.txt
输出: node_to_subgraph, core_schedules

Step 0: 图预处理
    - 提取 O_elig（非 COPY op）
    - 计算拓扑序 seq（Step1 或简化拓扑排序）
    - 构建 op-op 收缩邻接表
    - 计算 op 深度和关键路径

Step 1: 初始种群生成（P_size = 50）
    - 策略1 (40%): 基于拓扑区间连续切分（区间长度 50~150）
    - 策略2 (30%): 基于关键路径的分段切分
    - 策略3 (30%): 基于 op 亲和度的聚类切分
    - 对每种切分，用列表调度（CP优先）生成 core_schedules
    - 全部调用评估器验证合法性 + 获取 Makespan

Step 2: 代理模型初始化
    - 收集所有已评估个体的特征和 Makespan
    - 训练线性/岭回归模型: features -> Makespan

Step 3: GA 迭代 (max_generations = 100)
    For g = 1 to G_max:
        a) 锦标赛选择 → 交配池
        b) 双点交叉 (cross_rate = 0.8) → 新个体
        c) 混合变异 (mut_rate = 0.15) → 新个体
        d) 合并父代 + 子代
        e) 代理模型预筛选:
            - 对每个新个体提取特征
            - 用代理模型预估 Makespan
            - 选取预估 top M 个 + 精英个体
        f) 真实评估器评估：
            - 调用 multicore_cut_evaluate_problem_1.py
            - 获取 Makespan 和搬运量
        g) 适应度计算
        h) 精英保留 (e=10%) + 截断选择 → 下一代种群
        i) 更新代理模型 (每 10 代)
        j) 收敛判定

Step 4: 输出最优方案
    - 解码适应度最高个体
    - 输出 node_to_subgraph 和 core_schedules
    - 可选：对最优解再做 5 轮局部搜索微调
```

### 【计算步骤】

**步骤 0：图预处理**
1. 从 JSON 解析 $G$，提取 `tensors`、`ops`、`edges`
2. 构建 op-op 邻接表：对每条 op→tensor→op 路径桥接为 op→op 边
3. BFS 计算每个 op 的深度 $d(o_i)$
4. 识别关键路径（从入度为 0 到出度为 0 的最长路径）

**步骤 1：初始种群生成**
1. 策略 1（拓扑区间）：按 seq 顺序，以贪心方式切分为大小 50~150 的连续区间（在不超过容量预估阈值处切分）
2. 策略 2（关键路径）：沿关键路径分段，每段包含 30~80 个关键路径 op，非关键路径 op 归入深度最近的分段
3. 策略 3（亲和度）：计算 op-op 亲和度矩阵，层次聚类（average linkage），在距离阈值 0.3 处切割
4. 对每种策略生成的子图集合，运行列表调度获得 core_schedules

**步骤 2：代理模型训练**
1. 对种群中所有已评估个体提取 12 个特征（见数据分析报告第 4.2 节）
2. 用 Ridge 回归拟合特征→Makespan，使用 5 折交叉验证

**步骤 3：GA 迭代**（详见求解流程）

**步骤 4：方案输出**
1. 解码最优个体为 JSON 格式
2. 写入 `case_xxx_multicore_res.json`
