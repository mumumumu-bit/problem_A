# 赛题理解与分析 —— 《通用神经网络处理器下的多核调度问题》

---

## 赛题背景分析

### 【问题背景】

本赛题来源于华为自研的通用神经网络处理器（NPU）架构设计与编译器优化场景。该处理器采用**多核 SIMD AI Core 架构**，每个核心内部包含四条独立的执行流水线（Pipe）：

| Pipe | 功能 | 典型操作 |
|------|------|----------|
| PIPE_MTE2 | 数据搬运（DDR→片上） | COPY_IN |
| PIPE_MTE3 | 数据搬运（片上→DDR） | COPY_OUT |
| PIPE_M | 矩阵/卷积计算 | MATMUL, GEMM, CONV |
| PIPE_V | 向量运算 | RELU 等逐元素操作 |

每个核心配备两级片上缓存：**L1（524288 字节）**和 **UB（131072 字节）**。所有核心共享 DDR 总带宽（60 字节/周期）。计算图（DAG）中的每个操作节点将产生和消费张量（tensor），张量可位于 DDR、L1 或 UB 三种存储层级中。

核心问题是：**给定一个神经网络计算图（由操作节点和张量节点构成的二部有向无环图），如何在多核处理器上对图中操作进行切分、调度和排布，使得总执行时间（makespan）最小化，同时满足片上存储容量、流水线互斥和数据依赖等硬件约束。**

研究对象是一个 **op-tensor 二部有向无环图（DAG）**，op 节点代表计算或数据搬运操作，tensor 节点代表中间数据。每个 op 具有固定的执行周期数（cycles）和所属流水线（pipe），每个 tensor 具有固定的存储位置（DDR/L1/UB）和字节大小。

### 【现实意义】

该问题的现实意义体现在以下几个层面：

1. **编译器后端优化的核心环节**：深度学习编译器（如 TVM、MLIR、华为 MindSpore 等）在将神经网络模型部署到实际硬件时，必须解决计算图的切分与调度问题。本赛题所涉及的多核切图、内存分配、流水排布正是编译器后端的关键技术。

2. **硬件利用率的直接决定因素**：在给定硬件资源约束下，调度方案的优劣直接决定了处理器的吞吐量和能效比。优秀的调度策略可以充分挖掘指令级、流水线级和核心级并行性，显著缩短推理延迟。

3. **边缘端推理场景的迫切需求**：随着大模型向边缘端部署的趋势，有限片上存储与大规模模型参数之间的矛盾日益突出。本赛题涉及的缓存换入换出（Spill）问题，直接关系到如何在受限内存下运行超大规模模型。

4. **学术与工业界的交叉前沿**：该问题融合了图论（DAG 划分与拓扑排序）、组合优化（任务调度）、操作系统（缓存替换策略）和计算机体系结构（流水线并行、带宽共享）等多个领域，具有重要的学术研究价值和工程应用前景。

### 【数学建模目标】

需要通过数学方法解决的核心任务可概括为：

1. **计算图的划分与映射**：将原计算图 DAG 中的操作节点划分到若干子图，并将子图分配到不同核心上执行（需确定核心数、子图边界、子图间依赖关系）。

2. **核内操作的顺序优化**：在每个核内，确定操作的执行顺序，使得片上缓存峰值占用尽量小，减少数据溢出（Spill）需求。

3. **缓存换入换出策略设计**：当片上存储容量不足以容纳所有活跃张量时，决定哪些张量外溢到 DDR、何时换出、何时换回（决策为 Belady 最优策略提供理论基础）。

4. **流水线并行排布**：在满足数据依赖和流水线互斥的前提下，尽可能早地发射操作，最大化核心内多条流水线的并行度。

5. **多核并行执行模拟**：综合考虑跨核通信延迟、共享 DDR 带宽竞争、Cache 命中率等因素，最终计算出全局 makespan 作为优化目标。

## 问题拆解

### 【问题 1 分析】

**问题目标**：将计算图切分为多个子图，每个子图作为一个独立 Task 调度到指定核心。Task 内部经历完整的核内调度三步（拓扑排序 → 缓存换入换出 → 流水排布）。需要给出**切图方案（node_to_subgraph）和核心调度方案（core_schedules）**，使得全局 makespan 最小化。

**已知信息**：
- 100 个计算图数据文件（case_001 ~ case_100），规模从约 50 个 op 到约 1650 个 op
- 硬件配置：L1=524288B, UB=131072B, DDR带宽=60B/cycle
- Task 切换代价：同核 Task 间等待 100 cycles，跨核 Task 间等待 1000 cycles
- 原始图中已有的 COPY_IN/COPY_OUT 操作不计入切图范围（它们会自动插入）
- 核内调度算法（Step1/2/3）为确定性算法，同一个输入必然得到同一个输出

**求解目标**：
- 对每个计算图，给出 `node_to_subgraph`（每个非 COPY 操作→子图 ID 的映射）
- 给出 `core_schedules`（每个核心上子图的执行顺序列表）
- 评估指标：全局 makespan = max(所有操作的完成时间)

**数学本质**：**图划分 + 资源约束下的任务调度优化问题**。核心是将 DAG 划分为若干子图（分区），并分配至有限核心，在满足子图间偏序约束的前提下确定每核心上的子图执行顺序，使得总完工时间最小。可归约为带通信代价的多处理器 DAG 调度问题（NP-hard）。

**主要难点**：
1. **切图策略**：如何确定最优的子图数量和边界？切分过细会引入大量跨子图通信（COPY_IN/COPY_OUT）和 Task 切换开销；切分过粗则无法充分并行。
2. **搜索空间巨大**：100 个计算图中，大规模图可达 1650+ 节点，可能的切分与调度组合数呈指数级增长。
3. **评估函数是黑箱**：makespan 需要通过完整的核内调度模拟器计算，无法直接求导或用简单公式估算，优化过程需要大量仿真。
4. **跨子图依赖处理**：问题 1 中，所有子图间数据都必须通过 DDR 中转（COPY_OUT → DDR → COPY_IN），引入通信延迟。

---

### 【问题 2 分析】

**问题目标**：与问题 1 使用相同的计算图和切图方案格式，但执行模型不同——**同一核心上的所有子图合并为一个 Task**，同核子图间通过片上张量直接传递数据（不经过 DDR），仅跨核数据边才插入 COPY_IN/COPY_OUT。需要给出**切图与调度方案**，同时要求在核内调度 Step2 过程中给出**换入换出方案**，使得全局 makespan 最小。

**已知信息**：
- 与问题 1 相同的数据集和硬件配置
- 跨核 COPY 延迟：500 cycles（`cross_core_copy_delay_cycles`）
- 无同核 Task 切换开销（所有子图合并在一个 Task 内）
- 同核子图间张量保留在片上，不产生额外搬运
- Step2 采用 Belady 最优替换策略（换出"未来最久不用"的张量）

**求解目标**：
- 给出每核合并后的 Task 内子图执行顺序
- 给出每个核心上的换入换出记录（哪些张量何时换出/换回）
- 评估指标：全局 makespan（要求优于单核执行）

**数学本质**：**带缓存约束的多核 DAG 调度 + 缓存替换联合优化**。相比问题 1，减少了一种开销（同核子图间通信不需要 DDR 中转）但增加了一种新的优化自由度（核内换入换出策略直接由调度顺序决定，但也可以主动设计调度顺序来减少溢出）。

**主要难点**：
1. **片上存储容量受限是核心瓶颈**：L1 仅 524KB、UB 仅 128KB，大规模子图合并后极易溢出。切图和调度必须考虑片上缓存的驻留量。
2. **切图与换入换出的耦合**：子图划分决定了核内的张量生命周期分布，从而影响溢出频率；调度顺序影响 Belady 选择的 victim 集合。
3. **跨核通信与核内溢出的权衡**：切分较细可减少单核内存压力但增加跨核通信；切分较粗减少通信但增加溢出。

---

### 【问题 3 分析】

**问题目标**：在问题 2 的执行模型基础上，增加一个**只读 FIFO Cache**（容量 1048576 字节，命中带宽 250 字节/周期）。COPY_IN 操作在从 DDR 读取数据前，先查询 Cache；命中时从 Cache 读取且不占用 DDR 带宽，未命中时从 DDR 读取并在完成后写入 Cache（FIFO 淘汰策略）。需要给出最优切图与调度方案。

**已知信息**：
- 与问题 2 相同的数据集、硬件配置和任务模型
- Cache 容量：1048576 字节（1MB）
- Cache 命中读取带宽：250 字节/周期
- FIFO 替换策略：命中不更新顺序，淘汰时逐出最早插入的条目

**求解目标**：
- 给出切图与调度方案（同问题 2 格式）
- 额外给出 Cache 利用率分析（命中次数、命中率、命中/未命中字节数）

**数学本质**：在问题 2 的基础上引入**多级存储层次下的带宽优化**问题——Cache 的存在改变了数据搬运的成本结构，命中可节省 DDR 带宽，从而使多核并发时 DDR 带宽竞争得到缓解。

**主要难点**：
1. **Cache 行为依赖执行时序**：FIFO Cache 的命中与否取决于历史上 COPY_IN 的顺序和时间，这又取决于调度方案。这是一个循环依赖——调度影响 Cache 状态，Cache 状态又影响搬运时间进而影响调度。
2. **切图策略需适配 Cache 特性**：合理的切图应使跨核复用的数据尽量集中在时间上相近的 COPY_IN 之间，以提高 Cache 命中率。
3. **带宽竞争建模更复杂**：现在有 DDR 带宽池和 Cache 读取带宽池两个独立共享资源，需联合考虑。

### 小问题逻辑关系分析

#### 【问题链分析】

三个问题之间存在清晰的递进关系：

```
问题 1（每子图一Task + Task 切换开销）
    │
    │ 减少开销类型（同核子图片上直传）
    ▼
问题 2（每核合并Task + 核内溢出处理）
    │
    │ 增加硬件特性（只读 FIFO Cache）
    ▼
问题 3（+Cache 层次 + 双带宽池）
```

**数据共享**：三个问题共用 100 个计算图（case_001 ~ case_100）和硬件基础配置（L1/UB 容量、DDR 带宽）。各问题对 `node_to_subgraph` 和 `core_schedules` 方案的格式要求一致，但评估器不同。

**结果传递**：不是严格的结果传递关系。问题 1 的方案可迁移到问题 2 下评估（但结果不同，因执行模型不同）。问题 2 的方案可直接在问题 3 下评估（问题 3 是问题 2 的超集）。在实际建模中，可先针对问题 2 建立基础调度模型，再将问题 3 的 Cache 作为额外考虑层。

**递进关系**：从建模复杂度看，问题 1 涉及 Task 级调度（粗粒度），问题 2 需要精细的核内溢出管理（中粒度），问题 3 进一步考虑存储层次的带宽优化（细粒度）。整体构成**从粗到细、从简到繁**的建模递进。

#### 【整体解题思路】

推荐的建模路径如下：

```
Step 1: 理解核内调度算法（Step1/2/3 的确定性行为）
   │
Step 2: 建立图结构特征分析工具（节点度数、关键路径、张量生命周期、存储压力估算）
   │
Step 3: 设计切图策略（基于图拓扑和存储约束的 DAG 划分方法）
   │
Step 4: 设计核心调度策略（子图到核心的分配与排序）
   │
Step 5: 使用评估器反馈进行迭代优化（启发式搜索/元启发式/学习型方法）
   │
Step 6: 针对问题 2/3 的特性调整模型（合并 Task、Cache 感知）
```

## 关键变量分析

| 变量类型 | 内容 |
|----------|------|
| **输入变量** | 计算图结构（ops 列表：op 类型、pipe 归属、cycles；tensors 列表：pos 位置、size 大小；edges 列表：数据依赖关系）；硬件参数（L1/UB 容量、DDR 带宽、Task 等待周期、跨核 COPY 延迟、Cache 容量与带宽） |
| **输出变量** | 全局 makespan（总执行周期数）；每核/每 Task/每 op 的时间线；片上存储峰值及时间序列；数据搬运量（原图搬运 + 切图新增搬运 + 溢出搬运）；Cache 命中率与命中字节数（问题 3） |
| **决策变量** | `node_to_subgraph`：每个非 COPY op 到子图 ID 的映射，决定切图边界；`core_schedules`：每核心上子图/操作的执行顺序；核内操作拓扑序（Step1 输出，受切图影响的传递变量）；SPILL 决策（Step2 中的 victim 选择，由 Belady 规则自动决定但受调度顺序影响） |
| **影响因素** | 子图数量与大小分布（影响并行度和通信开销）；切图边界的张量生命周期（影响跨核通信量和片上存储压力）；同核子图顺序与跨核依赖（影响关键路径长度）；DDR 带宽竞争程度（影响 COPY 操作耗时）；Cache 访问模式（问题 3） |
| **约束条件** | 拓扑约束（操作必须在其所有前驱完成后才能执行）；Pipe 互斥约束（同一核心的同一 Pipe 同时最多执行一个操作）；片上容量约束（任意时刻 L1/UB 驻留总量不超过容量）；DDR 带宽约束（多个在途 DDR 搬运公平共享总带宽）；Task 激活约束（问题 1：前驱 Task 完成 + 等待周期；问题 2/3：跨核 COPY 完成 + 延迟） |

### 关键变量作用分析

1. **子图数量与边界选择**：是最核心的决策变量。子图数量过少，并行度不足，单核负载过大，片上溢出剧烈；子图数量过多，切图引入的 COPY_IN/COPY_OUT 开销和 Task 切换等待（问题 1）会显著增加。需要在通信开销与计算并行度之间寻找平衡。

2. **核心分配策略**：不同核心分配方案影响跨核通信量、各核负载均衡和关键路径长度。负载不均会导致部分核心空闲等待。

3. **片上存储峰值**：直接决定是否需要 SPILL 操作。如果调度顺序设计得当（如步骤 1 描述的"深度排序 + COPY_IN 延迟"），可以使张量生命周期压缩、驻留峰值降低，从而减少甚至避免溢出。

4. **DDR 带宽利用率**：多核并发 DDR 搬运时，带宽被平均分配，单个搬运耗时增加。这是影响 makespan 的关键非线性因素。

## 初步建模方向判断

### 【可能建模方向】

基于赛题特点，可能的建模方向包括以下几类：

**1. 图划分与聚类方法**
- 基于拓扑排序的连续区间划分（如现有 stub 方案）
- 基于最小割/谱聚类的图分区算法（如 Kernighan-Lin、METIS）
- 基于关键路径分析的层级划分

**2. 组合优化与启发式搜索**
- 贪心构造 + 局部搜索（变邻域搜索 VNS、模拟退火 SA）
- 元启发式算法（遗传算法 GA、蚁群算法 ACO、粒子群 PSO）
- 禁忌搜索（Tabu Search）

**3. 调度理论方法**
- 基于列表调度（List Scheduling）的启发式
- 基于关键路径优先（CP/MCP）的任务优先级
- 基于资源约束项目调度（RCPSP）的建模

**4. 机器学习辅助优化**
- 基于图神经网络（GNN）的图结构特征提取与 cost 预测
- 强化学习（RL）进行切图策略搜索（将切图建模为序贯决策）
- 监督学习预测子图执行时间（作为优化目标的快速近似）

**5. 数学规划方法**
- 整数线性规划（ILP）建立精确模型（仅适用于小规模）
- 约束规划（CP）表达复杂时序和资源约束

### 【判断依据】

1. **图结构特性**：计算图是具有明确拓扑结构的 DAG，图中的张量定义了数据流向和生命周期。切图本质上是将 DAG 的节点划分成若干连通分量（子图），同时最小化跨分量边（通信）——这与图划分问题高度契合。

2. **NP-hard 本质**：多处理器 DAG 调度是经典 NP-hard 问题。加上片上容量约束和张量生命周期管理，问题更加复杂。因此**精确算法仅适用于极小规模**，中大规模必须依赖启发式或元启发式方法。

3. **评估器是黑箱**：makespan 只能通过运行完整的仿真管线得到，无法获得梯度信息。这使得基于梯度的方法不适用，而**无梯度优化方法（如遗传算法、贝叶斯优化、强化学习）**更合适。

4. **大规模数据**：100 个计算图文件，最大的含约 1650 个 op。这要求算法具有良好的可扩展性。直接对每个图运行昂贵的全局搜索可能不现实，需要设计**轻量级代理模型**来快速评估调度方案的质量。

5. **评估器本身是确定性算法**：相同输入 → 相同输出。这一特性意味着优化过程可以缓存评估结果，避免重复计算。

## 赛题难点总结

### 【核心问题】

赛题真正需要解决的核心矛盾是：**在有限片上存储容量、有限共享带宽和有限流水线资源的多重约束下，如何协调多核之间的任务划分与调度，使得神经网络计算图的总执行时间最小化。** 具体表现为三个层面的权衡：

- **并行度 vs 通信开销**：更多子图 → 更多并行 → 但更多跨核通信和切换开销
- **存储压力 vs 数据搬运**：片上张量越多 → 计算越快 → 但越容易溢出 → 越需要 Spill 搬运
- **Cache 友好 vs 并行效率**：为 Cache 优化调度 → 可能牺牲流水线并行度

### 【关键难点】

1. **搜索空间组合爆炸**：对 N 个 op 的计算图，可能切分方案随 N 指数增长。即使限制子图大小（如 50~100），方案数量仍然巨大。核心数和调度顺序进一步扩大了搜索空间。

2. **评估成本高**：每次方案评估需要运行完整的核内调度三步 + 离散事件模拟，即使单次仅需毫秒级，百万次评估仍然是沉重的计算负担。需要设计高效的方案筛选和评估策略。

3. **多目标隐式耦合**：切图边界、调度顺序、溢出频率、带宽竞争、Cache 命中率等因素相互耦合，很难将问题解耦为独立的子问题求解。改变任何一个决策变量都可能产生意想不到的连锁反应。

4. **图结构多样性**：100 个计算图可能具有不同的拓扑特征（宽度、深度、关键路径、tensor 大小分布），统一的建模策略可能在部分图上表现不佳。需要算法具有一定的自适应能力。

5. **数学建模与工程实现的衔接**：核心调度算法已经以代码形式给出（Step1/2/3），建模过程需要在理解这些算法数学原理的基础上，设计出能在给定算法框架下最大化性能的切图与调度策略。

### 【后续建模重点】

1. **图结构特征提取**：设计一组能有效刻画计算图拓扑特征和张量生命周期特征的统计量（如关键路径长度、平均并行度、每层 op 数、最大张量大小等），作为后续优化的输入。

2. **切图策略设计**：重点研究基于图拓扑和存储约束的合理切分粒度。可能需要设计贪心构造规则（如基于关键路径的层级分组、基于张量生命周期的边界选择）。

3. **快速代价估计**：建立 makespan 的快速近似估计模型，避免每次决策都运行完整仿真。可考虑基于关键路径分析的下界估计、基于存储压力的溢出惩罚等。

4. **元启发式框架**：选择适合离散组合优化的元启发式框架（推荐遗传算法或模拟退火作为起点），设计合理的编码方案、交叉/变异算子和约束处理方法。

5. **问题间复用**：三个问题的模型应尽量复用核心组件（如图特征提取、切图策略），针对各问题的特殊约束（Task 切换开销、Cache 层次）进行增量调整。
