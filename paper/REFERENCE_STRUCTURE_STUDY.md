# 参考论文结构学习记录

## 使用边界

本文档只记录 4 篇参考论文的章节组织、图表安排和写作结构，不借用其算法、公式、实验数字、结论或参考文献。我们的论文事实依据仍唯一来自 `paper/EVIDENCE_MAP.md`；本文件不修改该文件，也不把参考论文中的机制补入 Evidence Map。

研究对象为以下 4 篇 PDF：

1. `A题-面向 Davinci 架构的 NPU 核内调度算法研究.pdf`
2. `A题-1-通用神经网络处理器下的核内调度问题.pdf`
3. `A题-2-通用神经网络处理器下的核内调度问题.pdf`
4. `A题-NPU 核内调度算法设计与优化研究.pdf`

## 一、4 篇论文分别分析

### 1. 参考论文一：面向 Davinci 架构的 NPU 核内调度算法研究

#### 1.1 总体章节结构

- 采用“前言—模型假设与符号—问题一—问题二—问题三—主要结论与模型评价—参考文献—附录”的完整竞赛论文结构。
- 前言内部包含问题背景、研究现状、问题重述、数据介绍和总体求解框架。
- 三个问题分别作为独立大章，每章内部继续展开问题分析、方法适用性、模型、求解、结果和小结。
- 最后一章集中写模型优点、不足和推广，形成统一收束。
- 附录分成 AI 工具使用规范说明和关键代码展示两个部分。

#### 1.2 问题分析章节结构

- 在前言中先说明硬件、计算图、缓存和调度背景，再分别重述三个子问题。
- 每个问题大章开头再次设置问题分析或核心方法适用性分析，把该问题的目标和难点具体化。
- 分析部分通常先讲问题的约束对象，再说明为什么需要某类求解框架，随后进入模型。

#### 1.3 模型章节结构

- 没有把三个问题的全部数学模型集中到一个总模型章，而是按问题分散组织。
- 问题一先给单目标规划模型，再给不同求解策略的模型和结果。
- 问题二先给调度序列、缓存分配和双指标目标，再给局部搜索与演化计算等求解安排。
- 问题三先给分阶段目标，再分别讨论约束下的加权优化和多目标前沿。

#### 1.4 算法章节结构

- 算法内容嵌入各问题章节，通常顺序为“适用性分析—算法/模型构建—流程图或伪代码—复杂度—实验结果”。
- 算法流程图在算法正式展开前出现，起到从问题分析过渡到实现细节的作用。
- 算法复杂度分析通常紧跟方法说明或实验设置之前，而不是统一放到全文末尾。

#### 1.5 三个子问题如何衔接

- 问题一产生调度序列或基础调度结果。
- 问题二在问题一结果基础上处理缓存分配、地址和换入换出。
- 问题三进一步把运行时间、搬运量或多目标性能放到综合优化框架中。
- 三个问题形成“基础调度—资源管理—综合性能优化”的递进链条。

#### 1.6 图表、优缺点与附录位置

- 总体框架图位于前言/总体方案部分。
- 每个问题的局部流程图放在对应问题的模型或算法开始处。
- 数据探索图和结构统计表位于相应问题的实验设计或结果前。
- 收敛曲线、策略对比图、最终结果表紧跟对应算法的结果分析。
- 末章集中放模型优点、不足和推广，不在每个问题末尾重复写完整评价。
- 附录放 AI 说明和关键代码，正文只保留理解算法必需的伪代码、流程图和核心定义。

#### 1.7 值得借鉴与不适合照搬

**值得借鉴的结构**

- 用一张总框架图先说明三个问题之间的输入输出关系。
- 每个问题都采用“问题分析—模型—算法—结果—小结”的闭环。
- 将模型局限与推广单独集中到结尾，避免结果章节过早发散。
- 通过问题小结不断回收上一问题的输出并引出下一问题。

**不适合照搬的地方**

- 不应照搬其多种算法并列、复杂多目标分阶段的安排；我们的 Evidence Map 只确认 Multi-seed + strict-descent VNS 主流程。
- 不应把参考论文中的缓存层级、目标函数、约束或算法名称替换成我们的机制。
- 不应照搬其较长的背景综述、算法比较和具体算例数字。

### 2. 参考论文二：通用神经网络处理器下的核内调度问题（A题-1）

#### 2.1 总体章节结构

- 采用六段式主结构：问题提出、问题分析、模型假设、符号说明、模型的建立与求解、模型的评价与改进。
- 三个子问题集中放在“模型的建立与求解”一章，整体篇幅短而集中。
- 参考文献之后设置 Python 源程序附录。

#### 2.2 问题分析章节结构

- 先写总体背景和问题提出，再单列“问题的整体分析”。
- 整体分析按问题一、问题二、问题三依次说明目标，并强调三者的递进关系。
- 后续每个子问题仍保留“求解思路”，避免整体分析和局部分析脱节。

#### 2.3 模型章节结构

- 在进入三个问题前统一列出模型假设和符号说明。
- 每个子问题均采用“求解思路—模型建立—模型求解与结果分析”的固定模板。
- 约束、目标和变量放在相应问题内部，不把三个问题的符号混成一个过大的模型表。

#### 2.4 算法章节结构

- 算法说明、伪代码、流程图与结果分析放在同一问题小节内。
- 先给思路图，再给算法细节，然后展示曲线、对比表和结果解释。
- 算法参数或实验设置位于算法和结果之间，便于读者理解结果来源。

#### 2.5 三个子问题如何衔接

- 论文明确把问题一视为基础调度结果，把问题一结果作为问题二的输入。
- 问题二在前一问题的调度序列上处理缓存分配和搬运。
- 问题三综合前两个问题的产物，进一步评价时间和搬运等指标。

#### 2.6 图表、评价与附录位置

- 全文总流程图位于第五章开头的“解题思路与流程图”。
- 每个问题的结果图表紧随该问题的求解小节，而不是集中到全文末尾。
- 模型评价与改进单列最后一章，包含优点、局限和可改进方向。
- 附录主要放完整 Python 源程序，正文只展示必要的算法描述。

#### 2.7 值得借鉴与不适合照搬

**值得借鉴的结构**

- “统一假设与符号—问题分章闭环”的组织方式清晰、篇幅可控。
- 每个问题都有相同的内部模板，读者容易定位目标、算法和结果。
- 将源代码放入附录，正文避免被实现细节打断。

**不适合照搬的地方**

- 不应照搬其较宽泛的硬件假设、缓存层级或多目标表述；这些必须以 Evidence Map 为准。
- 不应把其“问题三综合优化”的具体目标和算法当作我们的 P3 机制。

### 3. 参考论文三：通用神经网络处理器下的核内调度问题（A题-2）

#### 3.1 总体章节结构

- 采用“问题重述—模型假设—符号说明—问题一模型建立与求解—问题二模型建立与求解—问题三模型建立与求解—模型评价与改进”的顺序。
- 三个问题采用高度对称的章节结构，分别独立完成分析、模型、算法、实验和小结。
- 参考文献后设置 MATLAB 源程序附录。

#### 3.2 问题分析章节结构

- 问题重述中先定义整体背景，再逐条说明三个子问题及其依赖关系。
- 每个问题的大章开头设置“问题描述与分析”或“问题分析”。
- 分析部分同时承担“解释目标”和“说明为什么选择该求解路线”的功能。

#### 3.3 模型章节结构

- 每个问题内部按“问题分析—模型建立—模型求解—结果分析”展开。
- 模型建立通常再分为符号定义、目标函数、约束条件、可行解空间等层次。
- 模型与算法衔接紧密，但章节标题仍把“模型建立”和“模型求解”区分开。

#### 3.4 算法章节结构

- 先给总体框架图，再按初始化、主体搜索、参数调整、约束处理和复杂度等层次展开。
- 伪代码或步骤说明放在算法主体内。
- 结果分析不仅给最终指标，还安排数据集特征、缓存占用图、性能表和综合讨论。

#### 3.5 三个子问题如何衔接

- 问题一输出调度序列。
- 问题二在该序列基础上做缓存分配与换入换出。
- 问题三在前两个问题的方案上做双目标或综合性能提升。
- 每章末尾的“小结”用于确认上一阶段输出已经成为下一阶段的输入。

#### 3.6 图表、评价与附录位置

- 每个问题的总体流程图放在该问题建模或算法展开之前。
- 数据集特性表通常放在实验设计处，最终指标表放在结果分析处。
- 模型评价与改进集中在最后一章，不在各问题中重复进行全文式总结。
- 附录提供完整 MATLAB 实现，正文保留框架和必要步骤。

#### 3.7 值得借鉴与不适合照搬

**值得借鉴的结构**

- 三个问题结构完全对称，便于比较 P1/P2/P3 的目标、输入、输出和结果。
- 先给数据特征，再给性能结果，有助于把结果解释与实例规模联系起来。
- 每个问题都同时呈现框架图、表格和文字解释，图表不会脱离算法叙述。

**不适合照搬的地方**

- 不应照搬其具体算法、参数调节机制、复杂度结论和实验数字。
- 不应为了保持表面上的对称而给 Evidence Map 中不存在的 P1/P2/P3 数学子模型增加新目标。

### 4. 参考论文四：NPU 核内调度算法设计与优化研究

#### 4.1 总体章节结构

- 采用较完整的长篇结构：问题重述、模型假设、符号说明、问题一、问题二、问题三、算法通用性分析、模型总结与评价、参考文献、附录。
- 三个问题分别占据独立大章，每章包含问题分析、求解思路概述、问题建模、模型求解与结果分析、问题小结。
- 在三个问题之后增设“算法通用性分析”，再进入模型总结与评价。

#### 4.2 问题分析章节结构

- 问题重述部分详细说明背景、核心约束和三个问题的递进关系。
- 每个问题开头先写问题分析，再写求解思路概述；这一层级使“为什么这样建模”和“怎样实现”分开。
- 通用性分析单独讨论不同算子图和约束结构的适用范围。

#### 4.3 模型章节结构

- 统一假设和符号在前两章完成。
- 每个问题内部均有目标函数、约束条件、决策变量或策略模块的层层展开。
- 复杂模型把“模型构建”和“算法实现与优化”分成两个小节，先保证数学对象完整，再说明求解器如何处理。

#### 4.4 算法章节结构

- 每个问题先放整体框架图，再放算法实现与优化。
- 算法章节包含流程、策略模块、复杂度或终止性说明，结果章节随后验证性能。
- 论文末尾另设算法通用性分析，避免把“在测试数据上有效”直接扩大为“对所有任务普遍有效”。

#### 4.5 三个子问题如何衔接

- 三个问题明确采用逐级复用关系：问题一的调度结果进入问题二，问题二的缓存方案进入问题三。
- 每个问题结尾设置小结，既总结本问题，也为下一个问题准备输入。
- 最终再用通用性和模型评价对整个链条作统一收束。

#### 4.6 图表、评价与附录位置

- 问题一、二、三各有独立框架图，放在对应问题的求解思路或建模前后。
- 模型符号表、硬件资源表和数据集统计表放在模型或实验设计附近。
- 性能对比表、可扩展性表和雷达/趋势图放在各问题结果分析内。
- 通用性分析单独使用理论适用性、典型算子特征和局限性小节。
- 附录位于参考文献之后，用于承载实现材料。

#### 4.7 值得借鉴与不适合照搬

**值得借鉴的结构**

- “每个问题一个闭环 + 全文一个通用性分析”的层次最完整。
- 把框架图放在问题求解思路处，把结果图表放在结果分析处，阅读路径自然。
- 把适用边界和局限性单独写出来，避免用少量样本结果夸大推广结论。

**不适合照搬的地方**

- 不应照搬其大量理论定理、复杂策略模块、算法名称和性能结论。
- 我们的 Evidence Map 没有确认统一的缓存分配/换入换出双目标模型，因此不能为了模仿其篇章长度而添加此类模型。

## 二、4 篇参考论文的结构共性

### 高频有效结构

1. 摘要之后先完成问题重述或问题背景，使读者先知道任务对象、三个子问题和递进关系。
2. 模型假设与符号说明通常集中在前部，减少后文重复解释。
3. 三个子问题都采用相似闭环：问题分析 → 求解思路/框架图 → 模型 → 算法 → 实验结果 → 小结。
4. 框架图出现在算法或模型展开之前，结果图表紧随对应结果段落。
5. 结果章节通常同时包含数据特征、指标表、趋势图/收敛图和文字解释。
6. 末尾集中安排模型评价、局限、改进或推广；较长论文会另设通用性分析章。
7. 参考文献后通常放代码、AI 使用说明或其他复现材料。

### 适合 A 题的章节顺序

适合采用“统一问题定义 + 统一模型/指标 + 三个问题分章闭环 + 统一评价”的顺序。与四篇论文相比，建议保留对称性，但把我们的统一算法与三个评估场景分开，避免在 P1/P2/P3 中反复重复 Multi-seed + VNS 的全部细节。

### 模型与算法如何分开

- 模型部分回答：输入是什么、决策对象是什么、约束是什么、官方评价指标是什么。
- 算法部分回答：如何生成候选、如何排序、如何评价、如何进行 VNS、如何形成最终方案。
- 对本题，不能把候选排序启发式写成官方 makespan，也不能把 P3 的评估器 Cache 行为写成 solver 的 Cache-aware partitioning。

### P1/P2/P3 如何组织

- 先在统一模型章说明计算图、调度方案、评价指标和 P1/P2/P3 的执行模型差异。
- P1 结果章突出 Scene A 的多核切分与调度结果。
- P2 结果章突出 Scene B 的跨核 COPY 与扩展性结果。
- P3 结果章单独说明只读 FIFO Cache、P2/P3 的逐 case 对比口径和 Cache hit rate。
- P3 N=1 的 paired comparison 和 N=2～5 的 P2/P3 统计来源必须分别说明。

### 框架图应该放在哪里

- 一张“统一求解框架图”放在问题分析结束、算法总章开始处。
- 一张“Multi-seed + VNS 流程图”放在算法章节开头。
- P1/P2/P3 各最多设置一张场景关系或评估流程图，放在各自结果章开头；不重复绘制完全相同的求解器流程。

### 结果图应该如何分布

- P1：speedup 随 N 的图及必要的阶段结果。
- P2：speedup 随 N 的图及与 P1 的对比图。
- P3：no-L2/readonly-L2 对比、speedup 与 hit rate 图。
- 算法阶段对比图可放在统一算法有效性章节，避免在 P1/P2/P3 末尾重复。
- VNS gain distribution 和 Cache hit 与 speedup 的相关性图更适合附录或“进一步分析”，因为它们是探索性解释，不是机制因果证明。

### 哪些内容适合正文

- 统一问题定义、必要假设和符号。
- P1/P2/P3 执行模型差异。
- Multi-seed + strict-descent VNS 的主流程、8 个邻域的分类说明和官方 Evaluator 闭环。
- 正式配置的关键参数及其来源。
- 主要结果表、主结果图、统计口径和必要的限制说明。
- P3 只读 FIFO Cache 的实现事实，以及 paired comparison 的定义。

### 哪些内容适合附录

- 完整配置表、字段定义和较长的候选来源说明。
- 全部 case 的明细结果、补充图和逐 case 统计。
- 代码片段、伪代码细节、异常/缺失值检查记录。
- 图表生成口径、数据列映射和复算说明。
- AI 使用记录、Prompt/后处理留档（如最终合规要求且与正文区分）。

## 四、结构学习结论

- 最值得采用的是“四个统一前置层次 + 三个问题对称闭环 + 一个统一评价章”的骨架。
- 对本题，模型章节应说明真实的计算图、任务、评估器和指标；算法章节应单独说明 Multi-seed + VNS，而不是把三种场景写成三套算法。
- P1/P2/P3 的结果章节应保持独立，尤其要把 P3 的只读 FIFO Cache 和 paired comparison 口径说清楚。
- 框架图应出现在问题分析之后、算法展开之前；结果图应紧跟对应结果表和统计口径。
- 参考论文中的复杂多目标模型、额外算法、理论保证和实验数字均不属于我们的事实依据，不能因为结构上看起来完整而补入正文。
