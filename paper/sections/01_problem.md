# 1 问题重述

## 1.1 问题背景

本题研究多核 NPU 上的计算图划分与调度。计算图以操作和张量描述计算及数据依赖；调度需要把可调度操作划分为子图，分配至多个计算核，并确定各核上的执行顺序。不同划分会改变并行空间、跨任务数据搬运以及核内缓存的使用。题面设置了两种核间通信场景，并在第三问中加入所有核心共享的只读L2 Cache，要求考察这些机制对执行时间和数据搬运的影响。[CITATION-NEEDED: DAG上的多核NPU调度研究]

## 1.2 问题一重述

问题一对应没有核间同步机制的场景。给定题目中的计算图、固定配置和核数，需要为每个非 `COPY_IN`、`COPY_OUT` 操作指定子图编号，并给出各核上的子图执行顺序。每个子图单独构成一个 Task，子图边界的数据按场景规则经 DDR 搬运。方案须满足计算依赖和评估器的合法性检查；主要目标是缩短总体执行时间，同时关注额外数据搬运量。

题目要求在给定测试用例和固定配置下完成实验，报告1至5核的平均加速比，并在附录列出逐用例的 Makespan 与总额外数据搬运量，同时提供可复现的 Python 程序脚本。

## 1.3 问题二重述

问题二在具有核间同步机制的场景下，要求基于相同类型的计算图方案完成切图与调度。与问题一的关键区别是 Task 的组织和跨核通信方式：同一核心上的子图合并为一个 Task，同核子图之间可以复用 L1/UB 中的数据；跨核依赖则通过源核 `COPY_OUT`、目标核 `COPY_IN` 和题面规定的同步延迟传递。需要在 L1/UB 容量约束下缩短总体执行时间并减少额外数据搬运。

题目要求报告1至5核的平均加速比，并在附录提供逐用例的 Makespan、总额外数据搬运量及相应程序脚本。加速比口径与问题一相同。

## 1.4 问题三：共享L2资源下的多核切图与调度

问题三沿用问题二的执行场景，并加入所有核心共享的只读L2 Cache（以下简称共享L2 Cache）。需要研究其容量和带宽对多核切图与调度的影响，并建立相应模型和求解方法。FIFO用于说明该Cache在实现中的替换与更新规则，不替代题面所用的硬件名称。

题目要求比较1至5核下无 L2 与共享L2 Cache两种配置，并报告同核数下无 L2 Makespan 与共享L2 Cache Makespan 的比值。附录需按用例列出两种配置的 Makespan、总额外数据搬运量和 Cache 命中率。
